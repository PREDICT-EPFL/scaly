# Case study E7: factor-graph least squares (SymForce)

SymForce's robot 3D localization benchmark (Martiros et al., "SymForce: Symbolic Computation and Code
Generation for Robotics", RSS 2022, Table IV), run with SymForce's own C++ optimizer and generated code,
against the same problem and SymForce's own Levenberg-Marquardt generated by Scaly as one C function;
then a sweep of problem sizes, which SymForce's flattened "fixed" variant has to regenerate for.

```bash
examples/case_studies/symforce/baseline/setup.sh     # SymForce pinned and built twice, its generator in a venv
uv run examples/case_studies/symforce/compare.py --out examples/case_studies/symforce/results/sweep.json
uv run --with jupyterlab jupyter lab examples/case_studies/symforce/symforce.ipynb
```

`symforce.ipynb` explains the problem, builds and runs Scaly's solver without SymForce, compares its
iterates with SymForce's, and plots the recorded table and sweep. Its `RUN_BASELINES` flag reruns them.

## The problem and the two sides

Five poses in SO(3) x R^3 are estimated from 100 matching factors (every pose measures every one of 20
landmarks, sigma 0.1) and 4 odometry factors (sigmas 0.05 rad, 0.2 m), from identity poses: 324
residuals, 30 unknowns. The data are the example's (`gen/measurements.cc`, SymForce's generator with
seed 42).

**SymForce** (symforce-org/symforce at `6582930`, 2026-08-27; Eigen 3.5.0 from Homebrew):

- *dynamic*: one generated function per factor type, assembled by `sym::Optimizer` at run time;
- *fixed*: the whole problem's linearization as one flattened generated function (19 558 operations,
  528 kB of C++ at 5 poses), sparsity included.

`baseline/bench_symforce.cc` times what SymForce's benchmark (`symforce/benchmarks/robot_3d_localization`)
times, with the same calls: `Linearizer::Relinearize` (linearize) and `Optimize(values, 1)` repeated on
values its earlier calls update (iterate); and beside them the whole solve from the initial values.
Each is the best of 20 loops of 1000 calls (100 for the solve). SymForce's benchmark runs GTSAM and
Ceres too; they are not built here, since the plan's criterion is SymForce fixed. SymForce is built
twice, both at its Release flags (`-O3`) with `-mcpu=native`: as released, with its internal timers
(`SYM_TIME_SCOPE`) on, as its benchmark runs, and with the timers compiled out.

**Scaly** (`scaly_impl.py`): the residuals in SymForce's conventions (quaternions `[x, y, z, w]`, retraction
`R <- R Exp(dR)`, `t <- t + dt`, `Exp` and `Log` with SymForce's epsilon), each factor's Jacobian by
`sc.jacobian` in its tangent offset at zero inside a `vmap` body, `J'J` and `J'r` assembled on the
Hessian's fixed sparsity (`SparseMatrix.from_coo` sums the factors' blocks), and SymForce's
`LevenbergMarquardtSolver` as a `while_loop`: lambda from 1e4, halved on an accepted step and
quadrupled on a refused one, clamped at 1e6, unit damping, the generated sparse `L D L'`, stop when the
relative reduction is in (-1e-7, 1e-6) or after 50 iterations. Grouped (the default), one body
evaluates a pose's 20 matching factors, so the pose's rotation is formed once; per factor, one body per
matching factor, like SymForce's dynamic variant. Timed from C (`fatrop_chain/time_kernel.c`, the best
of 1 ms batches), at Scaly's JIT flags (`-O2 -mcpu=native -fno-math-errno`).

## Results at 5 poses (Table IV's problem)

Apple M3 Max, macOS 26, Apple clang 21. Not the reference machine of
[fairness](../../../docs/results/fairness.md); none of this belongs on the results pages. Microseconds:

| | Linearize | Iterate | Whole solve (11 iterations) |
|---|---:|---:|---:|
| SymForce dynamic, as released | 7.08 | 20.74 | 140.1 |
| SymForce fixed, as released | 2.42 | 10.50 | 75.1 |
| SymForce dynamic, timers off | 6.93 | 18.95 | 126.8 |
| SymForce fixed, timers off | **2.29** | 8.94 | 64.5 |
| Scaly, factors grouped by pose | 3.40 | **7.85** | **51.9** |
| Scaly, one body per factor | 4.27 | 12.15 | 77.2 |
| Paper (i7-9700K), SymForce dynamic / fixed | 15.1 / 5.4 | 47.0 / 25.6 | |

- **The same iterates.** Scaly's solver takes SymForce's 11 iterations with the same lambda at every
  one, accepts the same steps, and reaches the same errors to 7e-14 relative and the same poses to
  3e-15 (the error 132.35731922346 both sides).
- **Scaly is faster on the solve and on an iteration, slower on linearizing alone.** Against SymForce
  fixed with its timers off: 1.24x on the whole solve, 1.14x on one iteration, 0.67x on linearize.
  SymForce's flattened function shares every common subexpression across the whole problem; Scaly's
  grouped body shares them within a pose, and its advantage is in the rest of the iteration (one
  generated function with the damping, the factorization on a fixed pattern and the step, where
  SymForce's optimizer runs its general sparse machinery).
- **The plan's criterion** ("a full iteration below SymForce fixed's time at 5 poses") is met.
- SymForce's own timers cost it 2 to 17% (most on the iteration and the solve), which is in its published
  numbers.

## The sweep: 5 to 1000 poses

SymForce's own generator (`gen_symforce.py`, the example's `generate()` with its pose count changed)
regenerates the problem, data included, for each size; every pose sees 20 landmarks, so the problem has
`20 n + n - 1` factors. SymForce's fixed variant is generated while one generation fits 20 minutes; its
timers are off; microseconds for the whole solve / linearize / one iteration:

| Poses | SymForce fixed | SymForce dynamic | Scaly | Scaly vs the faster SymForce, solve | Iterations (both sides) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 5 | 66 / 2.3 / 8.9 | 126 / 6.9 / 19.0 | **52 / 3.4 / 7.8** | 1.27x | 11 |
| 10 | 229 / 8.1 / 27.7 | 305 / 14.3 / 38.3 | **124 / 6.8 / 16.2** | 1.85x | 13 |
| 20 | 616 / 29.3 / 78.4 | 618 / 29.3 / 77.3 | **243 / 13.7 / 32.8** | 2.5x | 13 |
| 50 | 1809 / 92.5 / 234 | 1626 / 71.0 / 198 | **639 / 35.2 / 83.2** | 2.5x | 13 |
| 100 | (generation over 20 min) | 4440 / 145 / 404 | **1739 / 70.6 / 167** | 2.6x | 18 |
| 200 | | 7977 / 287 / 812 | **3099 / 141 / 335** | 2.6x | 16 |
| 500 | | 20015 / 714 / 2023 | **7794 / 355 / 837** | 2.6x | 16 |
| 1000 | | 42763 / 1445 / 4107 | **16529 / 711 / 1672** | 2.6x | 17 |

What it takes to build each:

| Poses | SymForce fixed: generate, s | its `linearization.h` | C++ compile of the harness, s | Scaly: generate + compile, s | Scaly's C |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 5 | 2.5 | 0.53 MB | 12.0 | 1.6 | 131 kB |
| 10 | 8.0 | 1.08 MB | 16.4 | 1.6 | 160 kB |
| 20 | 32.5 | 2.24 MB | 27.8 | 1.7 | 219 kB |
| 50 | 312 | 5.85 MB | 83.0 | 1.6 | 409 kB |
| 100 | over 1200 | | | 1.6 | 725 kB |
| 1000 | | | | 2.0 | 6963 kB |

- **The same iterates at every size**: SymForce's iteration counts, lambdas and acceptances, errors to
  1e-12 relative and poses to 1e-14.
- **The gap widens, as the plan expected**: from 1.27x SymForce fixed at 5 poses to 2.8x at 50, and 2.5
  to 2.6x SymForce dynamic from 20 poses to 1000. Linearizing alone, Scaly is ahead from 10 poses.
  The flattened fixed variant stops paying at 20 poses (level with dynamic) and loses from 50 (5.9 MB
  of straight-line code).
- **No compile blow-up**: Scaly generates and compiles every size in 1.6 to 2.1 s, one body per factor
  type; SymForce's fixed generation grows about as n^2 (312 s at 50 poses, over 20 minutes at 100).
  Scaly's C grows linearly with the problem (7 MB at 1000 poses), but what grows is the index tables of
  the fixed sparsity (gathers, the summed coordinates, the factorization's analysis), not code: 93% of the
  C at 200 poses is constant tables, and they compile in the same 2 s.
- The workspace grows linearly too (840 753 doubles, 6.7 MB, at 1000 poses): every factor's blocks and
  the factor of the 6000 x 6000 Hessian are held at once.

## Files

| File | What it is |
| --- | --- |
| `baseline/setup.sh` | SymForce pinned, built as released and without timers, and a venv with its generator |
| `baseline/bench_symforce.cc` | SymForce's benchmark calls, and the whole solve, as a standalone program |
| `baseline/gen_symforce.py` | SymForce's own example generator for any number of poses |
| `scaly_impl.py` | the problem and SymForce's LM in Scaly; the data parser |
| `run_scaly.py`, `compare.py` | one size in Scaly, timed from C; the paper row and the sweep |
| `results/robot_3d_localization.json` | the 5-pose data, from SymForce's `measurements.cc` (Apache-2.0) |
| `symforce.ipynb` | the study as a notebook |

`tests/integration/test_case_study_symforce.py` checks, on a planar pose graph, the factor Jacobians in
a `vmap`, the Hessian summed by `from_coo`, and LM with `SparseLDL` inside a `while_loop` (against finite
differences and SciPy's `least_squares`), and the SO(3) conventions.
