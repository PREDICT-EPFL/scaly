Tier 1 primitives: code-editing plan

Covers items #1–10 of piqp_in_scaly_2026_09_25.html. No code has been written yet. 25 Sep 2026

Summary

The work is eight pull requests, ordered by dependency. Each one lands on its own with the full suite, ruff and ty green. Every new op follows the codebase's Where to add things recipe. Every new op also gets the same test set:

  • a NumPy value reference;
  • generated C run through the pointer ABI;
  • finite-difference, JVP-versus-VJP and sparse-versus-dense derivative checks, where the op is differentiable;
  • a structural-sparsity check;
  • scalarized and looped lowering compared against each other;
  • a mutation check proving the gate can fail.

Speed is tested the way the fuzzing note prescribes: structural invariants in tests/ (node counts, C size constant in trip count, index tables linear in nnz, no quadratic build paths), and wall-clock only in a perf study under internal/notes/ using the existing Google Benchmark harness.

Two regression guarantees hold throughout:

  • The six existing C snapshots stay byte-identical in every PR. The one deliberate addition is a new control corpus entry in PR 4.
  • No existing test changes behaviour, except that derivatives of minimum, maximum and abs now exist (see Q2).

Speed tests (structural, in tests/)

  • Constant-in-trip-count code: the program node count and the rendered C bytes for scan/while_loop are identical at lengths 10, 1 000 and 100 000, apart from the literal. The template is tests/integration/test_vmap.py::test_race_car_eq_primal_source_is_constant_in_horizon.
  • Linear-in-nnz metadata: accumulating-scatter and segment-op index tables have exactly nnz entries, and lowering emits one loop, not nnz statements, above the scalarize budget.
  • No quadratic build paths: the node count of the gather VJP is O(n) (today's _gather_vjp loops over every source element with an np.nonzero, which is O(n·nnz)). The test asserts that the node count at n = 20 000 is ≤ c·n. It does not measure time.
  • No dense fallback: the flop count of the rendered segment_sum SpMV (counted +/* tokens in the loop body × trip count) is proportional to nnz, not to m·n.
  • Generous compile ceiling for the largest case only, e.g. render of a 10⁵-length scan < 2 s, as a smoke guard rather than a benchmark.

Speed study (wall clock, outside tests/)

internal/notes/perf_2026_10_tier1/ with README.md + run.py, reusing benchmarks/harness/gbench.py. Numbers stay in the note. Per conventions.md they are cited nowhere else until they reach docs/results/.

  • RK4 rollout, N ∈ {10, 50, 200}: scan vs vmap vs chained calls. Measures runtime, render time and C size.
  • SpMV and SpMᵀV from gather + segment_sum vs dense matmul vs a hand-written CSC loop, on the race-car and chain KKT patterns.
  • reduce_max/norm_inf vs sum (should match), and select vs branchy C.
  • Build time of the gather VJP before and after PR 3.
  • Optional sanitizer pass: compile the control corpus with -fsanitize=address,undefined and at -O0 vs -O2, then compare outputs.

Standing rules for every PR

  • Run uv run pytest -n=auto, uv run ruff check, uv run ruff format --check and uv run ty check --error-on-warning. Every PR touches the IR or codegen, so the whole suite runs every time.
  • Regenerate tests/baseline/pytest_nodeids.txt with the recipe in contributing.md.
  • Mutation check for each new gate: perturb the implementation locally, record in the PR description that the gate went red, then revert.
  • Give each new public name a docstring, a re-export in scaly/__init__.py, and an entry in tests/test_import_boundaries.py. Give each new module an IMPORT_LAYERS entry. None is planned, since everything fits in existing modules.
  • Update docs/how_it_works/ir.md (op tables) and, where the ABI is touched, generated_interface.md. Add todo items starting at id 82.

PR 1 · Comparisons, bool, select, casts, isfinite, copysign #2#5

Foundation for everything else. Scalar and elementwise only.

Edits

  • ir/expr.py: ExprOp.LT, LE, EQ, NE (GT/GE are builder swaps), AND, OR, NOT, SELECT (arity 3), CAST (attr dtype), ISFINITE, COPYSIGN, each with an OpInfo and its NumPy rule. Comparisons return dtypes.bool_, with differentiable=False. Builders sc.where, sc.cast, Expr.__lt__ etc. Caution: __eq__ must stay structural, because hash-consing depends on it. Equality is sc.equal only, and a test pins this.
  • ir/expr_spec.py: SELECT's condition is bool and its branches share a dtype; logical ops are bool-only; CAST targets a known dtype; compare operands share a dtype (no implicit widening).
  • ad/forward.py, ad/reverse.py: SELECT gets select(c, ȧ, ḃ) and (select(c, ū, 0), select(c, 0, ū)). CAST float→float passes through, and int/bool are non-diff. COPYSIGN gets sign-based rules. Then (Q2) MINIMUM, MAXIMUM and ABS get subgradient rules via select, with ties at ½.
  • ad/sparsity.py: the SELECT pattern is the union of both branches (the condition carries no derivative). Compares are structurally zero.
  • ir/program.py: matching scalar ProgramOps and their category sets. ir/program_spec.py: rules. passes/lowering.py: _UNARY/_BINARY entries plus a ternary elementwise rule for SELECT. passes/arith.py: select(true,a,b)→a, select(c,a,a)→a, not not x→x, constant compares.
  • codegen/c.py: spellings (a < b), (c ? a : b), (double)x, isfinite, copysign. bool renders as uint8_t. fuse_elementwise.py: _EXPENSIVE_OPS unchanged, since none of these are libm-heavy. The one exception is copysign, which is cheap.
  • Non-float temporaries: pack_workspace already spills only floating slots, so bool and int temps stay on the stack. A test pins that a large bool temp renders as a stack array, not w +.

Tests

  • tests/ir/test_expr.py: dtype results, NumPy parity, and x == y staying structural.
  • tests/ir/test_verifier.py: bool/float mixing is rejected, and so is a non-bool condition.
  • new tests/codegen/test_control.py: a compiled parity grid over {−inf, −1, −0, 0, 1, inf, NaN}² for every compare, select, isfinite and copysign. NaN semantics (every compare with NaN is false except NE) are pinned against NumPy.
  • tests/ad/test_derivatives.py: finite differences away from kinks; exact subgradients at ties; ReLU and saturation derivative graphs compile; abs'(0)=0.
  • tests/ad/test_sparsity.py: the select union pattern; a select whose condition depends on x adds no Jacobian entries of its own.
  • tests/passes/test_arith.py: each new identity is applied, and constant compares fold.
  • Mutation checks: swap the SELECT branches in c.py, and make LT render as LE. Both must go red.

PR 2 · Reductions reduce_max/reduce_min, plus norm_inf/norm_1 builders #3

Edits

  • ir/expr.py: ExprOp.MAX, MIN are full reductions to a scalar, mirroring SUM (no axis, for consistency with sum). norm_inf(x) = max(abs(x)) and norm_1 sit next to norm_2/sumsqr as builders. Empty input is a verify error, because there is no identity element.
  • passes/lowering.py: a @lowers rule copied from _lower_sum. It initialises from src[0], then runs a REDUCE loop with maximum. NaN propagation matches np.max: fmax would drop NaN, so the rule uses x > acc || isnan(x) through PR 1's select.
  • ad/*: VJP is ū · onehot(x == max) / count, splitting ties per Q2. JVP is the same mask dotted with ẋ. ad/sparsity.py: the output depends on every input.
  • passes/program/scalarize.py: verify that the REDUCE-with-maximum pattern scalarizes. It should, since scalarize interprets the buffer stores.

Tests

  • Compiled parity including NaN, ±inf, all-equal ties and size 1. Scalar vs loop hint at sizes 3 and 5 000.
  • Derivatives: finite differences on distinct entries, the exact tie split, forward = reverse.
  • Structural: one loop, no per-element statements above the scalarize budget.
  • Mutation check: initialise the accumulator to 0 instead of src[0]. The all-negative test must go red.

PR 3 · Accumulating scatter, segment_sum, segment_max/segment_min; linear-time gather VJP #1#4

Edits

  • ir/expr.py: remove the uniqueness check in scatter, which then matches its docstring. segment_sum(values, segment_ids, num_segments) is a builder over scatter. New ExprOp.SEGMENT_MAX/MIN, with static segment_ids and an explicit fill value for empty segments (default −inf/+inf, as in NumPy). The NumPy rules are np.add.at and np.maximum.at.
  • passes/lowering.py _lower_scatter: indices statically unique → today's = store (byte-identical C). Otherwise the body becomes out[idx[i]] = out[idx[i]] + src[i] in a REDUCE-kind range, the same pattern as SUM, which scalarize already interprets correctly. Segment max/min use a fill-initialised output and a select-max accumulate.
  • passes/program/combine_scatter_sums.py: audit that it treats a repeated-index scatter correctly. It already combines "sums of scatters", so repeated indices inside one scatter are a new case.
  • ad/reverse.py: rewrite _gather_vjp as a single accumulating scatter(cot, indices, shape). This is O(nnz) instead of the current O(size·nnz) Python loop. The forward rule is unchanged. Segment max/min VJP uses the argmax mask, gathered back per segment.
  • ad/sparsity.py: the scatter rule becomes a union over sources per destination, and segment ops follow the same shape. passes/expr.py: the zero-propagation patterns extend to the segment ops.

Tests

  • Compiled parity vs np.add.at for random index multisets, including all-same-index, empty segments and a permutation (the unique path).
  • The hash-consing hazard test: a repeated-index scatter small enough to scalarize, differential against the loop hint. This is the only realistic stale-load path in Tier 1 without in-place carries.
  • Snapshot guard: all six baselines are unchanged, so every existing scatter hits the unique path.
  • Gather VJP: the dense Jacobian of gather with repeated indices vs finite differences, and a structural node-count O(n) test at n = 20 000.
  • Integration: tests/integration/test_sparse_primitives.py checks SpMV and SpMᵀV on random CSC matrices (density 1–20 %) and on a synthetic stage-banded KKT pattern against scipy.sparse (already a dev dependency). Jacobians w.r.t. the data vector must match the analytic ones.
  • Structural speed: the flop count of the SpMV body is ∝ nnz, and there is one index table of length nnz.
  • Mutation checks: turn the accumulating store into a plain store, and drop the zero fill. Both must go red.

PR 4 · scan: a sequential loop with a carry #6

API

carry_N, ys = sc.scan(body, init, xs=[(x, start, stride), ...], length=N)
# body: Function (carry, *slices) -> (carry', y)   ; ys stacks y per step (optional)

Edits

  • ir/expr.py: ExprOp.SCAN with attrs callee, length, starts, strides, output, modelled on VMAP. As with VMAP, there is one node per selected output and they share one invocation. function/sugar.py: the scan builder, next to vmap. ir/expr_spec.py: the carry's type is preserved and the slice bounds are in range.
  • passes/lowering.py: a @lowers(ExprOp.SCAN) rule that is a SERIAL for-loop calling the callee procedure. The carry uses ping-pong buffers addressed by (k mod 2)·|carry| views, and the parity is chosen so that the final carry lands in the output buffer. That means no copies and no aliasing between a procedure's input and output, so C-54 is not needed yet. Because length is static, the trip count is constant.
  • passes/program/*: hoist_invariant must not hoist carry-dependent work. unroll_unit_loops may unroll length 0/1. scalarize may expand a scan only under its existing budget. Where a pass needs to know about SERIAL loops with loop-carried state, add a RangeKind.SERIAL guard.
  • ad/forward.py: the JVP is a scan of jvp(body) over the augmented carry (carry, ċarry). ad/reverse.py (Q5): the forward scan also emits the carry trajectory as ys, then a reverse scan (negative stride) runs vjp(body). ad/sparsity.py: iterate the body's Boolean dependency matrix until it stops changing, which takes at most length steps and usually a few.
  • ad/sparse.py: sparse Jacobians of a scan go through the coloring path, and the coloring must not special-case it as a VMAP.
  • codegen/aot.py and solver.py: add SCAN wherever {CALL, VMAP} is enumerated (procedure collection).

Tests

  • tests/integration/test_scan.py (metamorphic): scan ≡ N chained CALLs ≡ a Python loop over the compiled body, for an RK4 rollout, a linear recursion x⁺ = Ax + Bu and a Kalman filter (whose covariance carry is checked against a NumPy KF). Lengths are 0, 1, 2, 3 (parity edges), 50 and 1 000.
  • Derivatives: the scan's Jacobian w.r.t. init and xs vs the unrolled Jacobian and finite differences; forward = reverse; sparse_jacobian scattered dense = dense; the Hessian of a scalar cost after a scan is symmetric.
  • tests/ir/test_verifier.py: a carry that changes shape or dtype, and out-of-range slices, are rejected.
  • Structural speed: program nodes and C bytes are equal at N = 10, 1 000 and 100 000 (the test copies test_race_car_eq_primal_source_is_constant_in_horizon); the render time of N = 10⁵ has a smoke ceiling; the trajectory workspace equals N·|carry|.
  • Snapshot: add the control corpus entry, a scan rollout whose body uses select, reduce_max and an accumulating scatter. This is a deliberate baseline addition.
  • Mutation checks: drop the parity swap, which must fail the length-odd cases, and make the reverse scan run forward.

PR 5 · while_loop with a max_iter guard #7

API

carry, n_iter = sc.while_loop(cond, body, init, max_iter=K)
# cond: Function carry -> bool scalar ; body: Function carry -> carry ; n_iter is int32

Edits

  • ir/expr.py: ExprOp.WHILE (attrs cond, body, max_iter, output), with differentiable=False. function/sugar.py: the builder. ir/expr_spec.py: cond returns a bool scalar and the body preserves the carry.
  • ir/program.py: one new statement op, BREAK_IF(scalar), valid only inside a SERIAL FOR. FOR gains an optional exit_var attribute that exposes the trip count after the loop. ir/program_spec.py and ir/text.py: a rule and the listing. codegen/c.py: if (flag) break;, with the loop variable declared outside the for when exit_var is set.
  • passes/lowering.py: a ping-pong carry as in PR 4, but the parity is only known at run time, so the loop ends with one final copy from buf[n mod 2] to the output. That is one O(|carry|) copy per call, not per iteration.
  • passes/program/*: every pass must treat a loop containing BREAK_IF as opaque. scalarize refuses it. unroll_unit_loops may not remove it, even with max_iter = 1, since the break still matters. hoist_invariant and fuse_elementwise may not move work across it. pack_workspace keeps both carry buffers live for the whole loop.
  • ad/*: JVP and VJP raise with a message pointing at #10. ad/sparsity.py: the transitive-closure fixpoint of the body's pattern (conservative).

Tests

  • tests/integration/test_scan.py: Newton on a scalar and on a 5-D root problem (iteration counts and roots match a Python loop); an always-false condition gives 0 iterations and returns init; an always-true condition gives max_iter and equals scan(max_iter); NaN in the carry with a guard via isfinite.
  • tests/passes/test_program.py and test_scalarize.py: one test per pass showing a BREAK_IF loop comes through untouched. tests/ir/test_program.py: a BREAK_IF outside a FOR is rejected.
  • tests/codegen/test_control.py: the rendered C contains exactly one loop with the guard, and the n_iter output is exact.
  • Structural speed: C size is constant in max_iter, and there is exactly one carry copy per call (counted in the program IR).
  • Mutation checks: an off-by-one on the guard, and an inverted break condition.

PR 6 · In-place carry updates (a conservative donation rule) #8

Needed for LDLᵀ (Tier 2), where each step touches a few entries of an O(nnz) carry. With ping-pong alone, every step rewrites the whole carry.

Edits

  • Add the Expr builder index_add(base, idx, vals) = base + scatter(vals, idx, base.shape) (and index_set). These are builders only, recognised as a pattern at lowering.
  • passes/lowering.py: inside a scan/while body procedure, when the carry output is an index_add/index_set chain rooted at the carry input, and every other use of the carry input feeds into that chain's vals, then the body writes in place and the scan uses a single buffer. Otherwise it falls back to ping-pong. The second condition is a sufficient condition that every read happens before the write, and the Expr DAG can check it statically.
  • This is the C-54 minimum. Program passes must not merge a load across the in-place store inside a donated body. Mark donated procedures attrs["in_place"] and restrict scalarize on them to its interpreting mode, which is already store-ordered. Any value-sharing pass must skip them.

Tests

  • The same metamorphic suite as PR 4, with every donated case checked against the forced-ping-pong result (a test-only switch).
  • Negative cases, each of which must fall back: the carry input is also read by a y output; it is read after the update; there are two updates with an intermediate read.
  • A stale-load regression test: a small donated body where the same carry entry is read, updated, then read again in the next iteration, scalarized and looped.
  • Structural speed: in a donated scan, the stores per step equal |idx| (not |carry|), and the workspace holds one carry, not two.
  • Speed study: a toy left-looking column update, comparing a donated scan, ping-pong and unrolled.
  • Mutation check: relax the second condition so it is not enforced. The negative-case tests must go red.

PR 7 · Integer and bool outputs through the ABI #9

PR 8 · Custom derivatives on a Function #10

API

f = sc.custom_derivative(f, jvp=f_jvp, vjp=f_vjp)   # either or both
# f_jvp: (inputs, tangents) -> output tangents ; f_vjp: (inputs, outputs, cotangents) -> input cotangents

Edits

  • function/model.py: optional custom_jvp/custom_vjp Function attributes, carried through _from_exprs, hashing and naming. function/sugar.py: the builder.
  • ad/forward.py and ad/reverse.py: at a CALL, prefer the custom rule. A missing direction falls back to differentiating the body, and raises if the body is non-differentiable (e.g. contains WHILE). ad/sparsity.py: uses the primal body's structural pattern unless a sparsity override is given.
  • Check the lowering-hint preservation of C-55 for derived functions built from custom rules.

Tests

  • The canonical case is a Newton while_loop solving g(x, p) = 0, with a custom VJP via the implicit function theorem. Its dx/dp must match finite differences and the analytic answer.

  • sparse_jacobian through a custom-derivative call vs dense.
  • Mutation check: bypass the dispatch. The "deliberately wrong" test must go red.
