# Stored-coordinate derivatives

Issue #46 keeps sparse tangents on the primal's stored pattern. Their storage is
`(nseed, nnz)` per matrix, where nnz is the number of stored entries, with shared
constant index tables across seed kernels. The existing elementwise partial table evaluates on stored coordinates. A product
with one sparse operand keeps that operand sparse in forward mode. Reverse mode
samples the cotangent for its sparse adjoint and scatters stored contributions for
the dense adjoint. It does not form a dense outer product or project the sparse
primal through a dense matrix. Sparse movement adjoints scatter into stored slots.
Pass-through outputs compose input and output layouts in the final write.
`values()` outputs write canonical values directly without a temporary for reordering.
All ten supported sparse unary partials and the three binary maps are checked
against NumPy differences in both derivative modes.

The structural product join in `ad/sparsity.py` already implements the required
matrix-product dependency rule. The workload gates pin it against devrush's
results. A perturbation replacing it with an empty relation fails the comparison.

The 48 Maros-Meszaros problem archives and LICENSE are copied unchanged from
`origin/devrush:src/scaly/testing/data/maros_meszaros/`. NOTICE retains the upstream
attribution and records the new references. Reference pattern archives were generated by importing the frozen modules through `git show`,
without copying their implementation. `tests/integration/test_sparse_kkt.py`
rewrites the regularized Karush-Kuhn-Tucker system stated by
`src/scaly/opt/ipm/kkt.py::Kernels.kkt_matrix`, exercised by
`internal/notes/perf_2026_09_26_tier3/t3_3_kkt.py`, with main's public API. Numerical
references come independently from SciPy and central differences. Both the full
system and the interior-point method (IPM) upper triangle use P's upper-triangular input values, with the off-diagonal
values shared by their mirrored entries. Numerical inputs zero the free inequality
rows as IPM preprocessing does. All 48 stored patterns and KKT-value Jacobians
agree with devrush, as do each product's Jacobians in its vector and matrix data.
Factoring and solving the systems, and sparse-sparse products, remain outside
this task.

## Gates and perturbations

- Restoring either old dense projection fails the banded sparse-leaf memory gate
  at n=100, with a 10,000-entry private buffer. The corrected gradient and sparse
  Hessian also pass at n=400, including SciPy values and finite differences.
- Changing the sampled vector adjoint's coefficient fails both product directions.
- Replacing multi-seed sparse gather tangents with zero fails all four region
  derivative gates. Returning zero from forward differentiation fails all 17
  kernel and region finite-difference cases.
- Disabling the shared row-pointer table produces five copies and fails the
  multiseed gate. The correct lowering emits one.
- Allocating sparse intermediates by mathematical shape fails the KKT memory gate.
- Corrupting a saved devrush Jacobian coordinate fails the pattern comparison.
  Separate corruptions of the IPM upper-triangle Jacobian and a product's
  matrix-data Jacobian also fail their comparisons.
- Restoring the old boundary copies fails five direct-output cases, including
  a batched shared output with different declared layouts.
- Returning zero elementwise tangents fails all thirteen unary and binary
  partial checks.
- Eight large-leaf movement gates check gradient and sparse Jacobian buffers
  before and after optimization for slice, matrix and vector gather, and scatter.
  The 512 by 512 band has 1,534 stored entries. Restoring the old reverse rules
  fails the slice, vector-gather and scatter gradient gates with 262,144-entry
  buffers. Restoring the old forward rules fails the matrix-gather and scatter
  sparse Jacobian gates with 131,072- and 262,144-entry buffers. All eight pass
  with the stored-coordinate rules.
