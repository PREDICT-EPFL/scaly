Scaly branch review

Everything on claude/function-templates beyond main: 161 commits, ~90k lines added, reviewed at the templates P1b-i commit (the uncommitted P1b-ii edits are not included) · 27 Sep 2026 · eleven parallel reviewers, one per subsystem, each working from AGENTS.md, codebase.md and conventions.md; correctness claims re-run by me against a clean checkout of HEAD

Summary. The pieces are careful. Almost every compiler path is checked against an independent reference (NumPy, finite differences, unrolled twins, a NumPy PIQP validated against vendored PIQP), import layering is enforced, and rule 7 mostly holds. The debt is structural, and it is concentrated.

  • I reproduced thirteen bugs at HEAD, one of them in the docs. Six give wrong results with no error. The worst is that sc.solver(..., "piqp") accepts |x| in an objective as quadratic and solves the problem without it.
  • Five modules have outgrown their one-line ownership: passes/lowering.py, ad/forward.py, codegen/aot.py, ConcreteFunction in function/model.py, and Solver.step in the IPM.
  • Several concepts have two or three homes that already disagree: the per-op derivative rules (three copies), the sparse LDLT (three implementations with different rounding), the C translation unit (two assemblers), name reservation (four allocators, plus suffixes like _fwd and _inplace that carry meaning).
  • Hand-rolled caches and generated names miss part of their context: 13 AD caches ignore sc.options, the JIT key ignores the compiler, SparseLDL names come from a process-global counter.
  • Recursion on the Python stack is back in three places (delinearize_loops, the forward traversals, _depends_on). A 200-step elementwise chain on an 8-vector no longer compiles.

Suggested order: fix the silent-result bugs, then the crashes, then tidy ConcreteFunction before templates P2 adds instances and caches to it. The per-subsystem lists at the end hold every finding (about 250) as a work list.

Structural themes

1. Five modules have outgrown their ownership line

  • passes/lowering.py (2245 lines) holds the driver, about 30 rules, three factorization kernels, loop lowering and a 360-line in-place alias analysis that emits no program IR. Split it into a passes/lowering/ package (driver and registry, elementwise, structural, linalg, sparse, control, indexing), move the alias analysis to its own module with one prover instead of two, and have lowers() reject a second registration for an op.
  • ad/forward.py (1531 lines) holds two forward traversals with different seed APIs, four near-duplicate single/multi-seed loop builders that have already diverged (only one handles length == 0), the VMAP seed strategies, and ten helpers that reverse.py imports, which contradicts autodiff.md's "share no dispatch". A split into rules, loops, mapped and the traversals follows the existing seams.
  • codegen/aot.py (511 lines) is the CModule, the observer protocol, the C header, a second translation-unit assembler, the public API, the CLI and a graph walk.
  • Solver.step is 200 lines over nine PIQP phases. One method per phase, named after PIQP's routine, would make it checkable line by line against upstream. Name the bare constants too; 0.666 looks like a typo someone will "fix" to 2/3.

2. Each op's derivative is written three times

_jvp, _jvp_many_structural and _local_vjp each spell every partial derivative; the ERF factor appears three times. The multi-seed table already lacks abs, asin, acos, atan, atan2, min, max, the max/min reductions, segment extrema, index_add/index_set and copysign. A missing rule makes jvp_many rerun the whole expression once per seed, and a rule returning the wrong shape also falls back instead of raising. The suite only notices in the 69 tests that monkeypatch SCALY_STRICT_JVP_MANY. One table of partials per elementwise op, from which all three modes follow, removes the drift; an autouse strict-mode fixture makes the next gap fail loudly. codebase.md's "a scalar math op touches seven files" also undercounts by one.

3. Caches and names that miss part of their context

  • 13 AD caches without the options (bug 6), a JIT key without the compiler, and SparseLDL default names from a global counter (sldl{n}) that reach C symbols and the cache key, so the same graph rebuilt in one process renders different C and recompiles. Naming by a digest of the tables fixes the last one and retires the "names must differ" workaround in examples.
  • Name reservation has no owner. Four allocators in passes/program use different rules, delinearize_loops reserves nothing, lowering spells loop variables ad hoc, _inplace and _fwd suffixes carry meaning, and the lam:/fwd: input protocol is spelled 46 times with no collision check (nesting sc.forward collides). One program-wide authority seeded with every user name and every C/libm reserved word would close bugs 11 and the _inplace row together.

4. The renderer decides things (rule 4), and entry points lower twice (rule 5)

  • _force_noinline_raw returns "_fwd" in proc_name. It is a workaround for Apple clang 17 on every compiler, it also matches user names like car_fwd, and its pointer docs/macos_clang_call_miscompile.md is broken (the note is in internal/notes/). A PROC attribute set where AD names the helper, gated or given an expiry in todo.md, fixes all three.
  • The CasADi gather is emitted at render time, invisible to pack_workspace and to viz. The entry's SZ_W is assembled in eight places.
  • Two translation-unit assemblers (render_program_c and _render_solver_bearing_source) share private helpers and find the main PROC differently. render_c_source, render_c_api_header and workspace_size each lower on their own, and test_c_snapshot.py lowers twice for one pair.
  • DENSE_UNROLL = 8 in lowering is a second home for Options.dense_unroll, used as a fallback when the attribute is missing.

5. ConcreteFunction is a state bag, right before P2 adds more

  • Other modules attach descriptor, custom_jvp, custom_vjp and custom_sparsity after construction. descriptor has no default, so solvers/graph.py detects a solver by duck typing.
  • Four copy paths each re-list the eight _init_graph arguments and decide what survives; with_device drops the custom rules and the descriptor. _with_trees mutates self while every other with_* copies.
  • _from_exprs is the real low-level constructor: 589 test lines, 23 example sites, two guide pages. It cannot take trees, so callers patch the result with _with_trees.
  • Output sparsity lives in output_sparsities and in output_tree.sparsities; output_coloring_widths is threaded through five paths for one benchmark reader.
  • The five derivative wrappers in api.py share one body and re-spell {kind}_{of}_{wrt} nine times, plus nlp.py hand-writes sphess_gamma_.... These names are C symbols.

Before P2: one _replace(**changes) copy path, descriptor = None by default, a public constructor that takes trees, and one _derive behind the wrapper overloads. P2 multiplies whatever state handling exists when it lands.

6. The solver layer's seams

  • QP and NLP share a 15-key string dict from nlp._lowered (a misleading name here), which qp.py mutates (cached["qp_hessian"]) for a later reader. A frozen dataclass in _oracle.py would give the proof's Hessian an explicit field and a home for the duplicated _bound and concat helpers. The QP path also builds and discards the whole NLP oracle set.
  • The host seeds every NLP descriptor with IPOPT's print_level and sb and every QP descriptor with PIQP's verbose; scaly-sqp silently drops them, so options={"print_level": 5} on SQP is ignored. solver_plugins.md says desc.options is the user's dict.
  • Each plugin re-derives the core-owned typed signature (offsets, 2*nv+1 group indices), fills the stats struct field by field (four blocks) and normalizes infinite bounds its own way (three idioms, three NaN policies, and IPOPT's threshold of 2e19 against its own 1e19 option).
  • The generated IPM has no front door. examples/qp_solvers/generated_piqp.py imports six private helpers from qp.py. A public extract_qp seam is needed before Tier 4's backend="scaly", which cannot satisfy SolverBackend as it stands.
  • The PIQP dense path's "column-major staging" copies do nothing; PIQP's C interface is row-major, so these are three O(n2) copies per solve. The two build hooks share about 90 identical lines and judge "already built" by path existence, so a pin bump goes stale locally.

7. One sparse LDLT, three implementations

schedule="unroll" builds one Expr per multiply-add, "loop" emits the SPARSE_LDL op pair that lowering.py spells again, and "scan" is a third version. They round differently (unroll divides by d, the others multiply by 1/d and use blocked sums), so the factor's bits change when work crosses sparse_unroll. "auto" never picks scan; it survives as the differentiable fallback and keeps Segment, CostModel and the segment DP alive in symbolic.py. One op pair with an unroll attribute and its own derivative rule, as the dense ops already do, would let scan go.

8. Speculative and dead surface

The house rules call each of these a defect: the GPU scaffolding (cuda/opencl/metal DeviceSpecs, KERNEL/LAUNCH/BARRIER, six unused RangeKinds, sc.BACKEND_SUPPORT) that exists only to raise "deferred"; the structural_key API; format_expr beside render_expr_assembly; five unreachable zero-fold patterns; the lowering hint in the intern key with three merge policies, where opaque behaves as block; render_solver_raw(include_external_sources=...), SolverDescriptor.runtime, BufferType, SolverStatus, the paths.py migration fallback, the codegen/__main__.py shim, can_render_program_c, scaly-sqp's dense QP mode (one caller, a test), and 13 names in sc.__all__ that nothing uses.

9. Tests: strong oracles, drifting structure

  • tests/ no longer mirrors src/. integration/ is the largest directory and holds unit tests of sugar.py and forward.py internals; there is no test_sugar.py, test_forward.py or test_reverse.py; twelve program passes share one 921-line file; tests/viz/test_recording.py tests benchmarks.harness.
  • Some gates are weaker than they read. The "Program IR migration harness" compiles 32 functions and checks only that outputs are finite. test_import_boundaries.py checks about 25 of 123 public names. The PIQP decision gate skips cases at run time whenever PIQP's own backends disagree, a set that depends on the compiler.
  • The node-ID baseline changed in 75 of the 161 commits and aborts a local run before any test executes; CI already enforces it. Nine files draw from a module-level RNG, so under xdist a test's inputs depend on what ran before it. Three tests assert wall-clock time. There is no --strict-markers, and the suite writes into the developer's real JIT cache.

10. Docs and repository

  • delinearize_loops appears in no doc (architecture.md step 8 and pass list, lowering.md, the codebase.md map; visualization.md says eleven passes). utils/options.py is missing from the map.
  • AGENTS.md, contributing.md and architecture.md say NumPy is the only runtime dependency. pyproject and README say NumPy and SciPy, and six modules import SciPy at load time.
  • The API reference says anything it does not list is internal, and it omits about 34 public names, including scan, while_loop, custom_derivative, SparseMatrix, sc.options and all of scaly.linalg.
  • docs/guide/linalg.md carries timings from non-reference machines and cites unpublished internal/notes reports. docs/.DS_Store and docs/.obsidian/*.json were committed on this branch in the Tier 2 review round.
  • examples/ is outside ruff's include list; examples/casadi, simple.py and multiple_shooting.py are never run; four examples still teach the pre-params= while-loop pattern. No published snippet is executed, which is how bug 13 shipped.
  • Benchmarks: run_checks is copied into four problems, closed_loop.py hard-codes every problem, the harness writes function._compiled, and three more measurement harnesses live in examples/ (the qp_solvers C timer lacks the macOS CLOCK_UPTIME_RAW fix). CI and the benchmarks README use uv run python ..., which AGENTS.md rules out.
  • internal/todo.md is 1122 lines with 97 checked and 38 open items. As "the single actionable list" it now reads mostly as a changelog.

Suggested order

  1. Bugs 1 to 6, each with a test that fails first. They are small patches.
  2. Bugs 7 to 12: iterative walkers in delinearize_loops and the forward traversals, dtype-aware zero tangents, the zero tile, and one name authority.
  3. Theme 5 before templates P2.
  4. The lowering package split, one partials table for AD with strict mode as the test default, one translation-unit assembler.
  5. Theme 6 before Tier 4: extract_qp, the normalized-problem dataclass, plugin-owned option defaults, core helpers for the signature, stats and bounds.
  6. The deletions in theme 8 and the docs fixes in theme 10, as one sweep.

Worth keeping

  • The differential oracles: the NumPy port of PIQP validated against vendored PIQP through a trace driver, and finite-difference and unrolled-twin checks across AD, linalg and loops. tests/codegen/test_control.py (table-driven, a NumPy reference per op, signed zeros, infinities, NaN, both lowering modes) is the pattern to copy for the missing op coverage.
  • Import layering enforced statically and by fresh-interpreter imports, the single _jit() seam, and the viz observer inversion.
  • ad/sparsity.py and passes/affine.py are model modules: AD-free, well bounded, exact, with why-comments.
  • Builders fail at construction with specific messages, and unsupported lowerings raise instead of degrading.
  • The IPM's docstrings name the PIQP routine each piece mirrors and state each deviation with its reason; Settings mirrors PIQP's names and defaults one to one.
  • The vendored-build tricks are explained beside the code, and the pins live in one build_config.json read by the hook, provenance and the CI cache key.
