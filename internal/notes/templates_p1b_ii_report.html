Function templates P1b-ii: one argument per parameter

2026-09-27 · branch claude/function-templates · plan v2, step P1b-ii

Summary. A body takes one argument per declared parameter: @sc.function(3, (), output="f") def cost(x, p), called cost(x, p). Slots may be shorthand: a shape or a name. Unnamed leaves take the parameter's name. Seeded derivatives append their seed, fwd(x, p, v), and solvers take five arguments. The whole tree is migrated: 130 call sites in tests, plugins, examples, notebooks, benchmarks and docs. The generated C is unchanged and the Python call path got faster (2.83 to 2.44 µs for one leaf).

What changed

  • Parameter lists. ConcreteFunction.input_tree is always tree.param_list(*slots), a private group whose parts are the parameters. The trace calls fn(*symbols). __call__, symbolic_call and numerical_call are variadic, with one dispatch pass over all leaves (tree.is_symbolic_call replaces Tree.is_symbolic/is_numerical). A call with no arguments is numerical; f.symbolic_call() is the symbolic spelling. A wrong count raises cost() takes 2 arguments (x, p), got 1.
  • Keywords bind through the body's inspect.Signature, only when keywords are passed; binding on every call would cost about 1 µs. Functions with no body (_from_exprs, derivatives, solvers) are positional-only. Statically, keywords are refused on declared functions: the width ladder gives positional-only parameter lists.
  • Decorator. sc.function(*slots, output=, name=) with a typed ladder for widths 0 to 8 plus an untyped catch-all. A slot or output is a tree spec: a Tree, a shape (3, (n, m), a TensorType) or a name (a leaf with a shape hole). Shorthand types as a leaf through TypeVar defaults (typing_extensions, under TYPE_CHECKING). sc.G takes specs too.
  • Names. sc.L and sc.S may be unnamed (sc.L(3), sc.L(), sc.S(pattern)). The decorator names each slot after its parameter (p, or p_0, p_1, nested p_0_1 inside a group) and unnamed outputs after the function (f, or f_0, ...). An unnamed leaf traced anywhere else (sc.problem, say) is refused with the fix. sc.L gained dtype= and diff=; sc.L(None) is refused rather than meaning a scalar.
  • Conventions. forward/adjoint: (*source parameters, seed). lagrangian_hessian and the sparse one: (*source parameters, lam), where lam has the output tree's shape. Solvers: five slots, built by param_list in qp.py, nlp.py and the sqp plugin's external.py. Solver results are typed ConcreteFunction[[SV, SV, Expr, Expr, SP], [NV, NV, ndarray, ndarray, NP], ...]. _from_exprs keeps a single group slot, and so do the NLP oracles, so their many call sites are unchanged.
  • C names. Parameter names now become C names by default, so c_ident reserves the C and C++ keywords (new becomes new_). A test compiles the headers of def keywords(new, this) as C++.
  • JIT seam. _jit() keeps the module after the first import: the import statement cost 0.32 µs per call.

  • The smoke benchmark's solver_call case failed before this branch: a host function and its solver were both named smoke_safety_filter_qp, which lowering refuses. The solvers are renamed ..._qp_piqp and ..._nlp_ipopt.
