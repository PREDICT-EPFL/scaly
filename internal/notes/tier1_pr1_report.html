New capability

Scaly graphs can now make data-dependent choices without leaving the expression dialect:

relu = sc.where(x > 0.0, x, 0.0)                    # select, differentiable through the chosen branch
ok   = sc.isfinite(r) & (sc.norm_2(r) <= tol)       # bool expressions, combined with & | ~
step = sc.copysign(sc.sqrt(d), b)                     # sign transfer
cnt  = sc.cast(active, "float64").sum()               # bool → float
  • Comparisons < <= > >=, sc.equal and sc.not_equal produce bool. == between two expressions stays structural identity, because hash-consing relies on it.
  • An Expr now has no Python truth value. if x < y: raises instead of silently taking one branch for every input.
  • A Python number takes the dtype of the Expr beside it, and mixed-dtype operations are still refused.
  • bool crosses the double ABI:
    • An output is written as 0.0 or 1.0, and Python gets back a NumPy bool array.
    • An input reads any nonzero value as true.
    • Float-only functions are unaffected: their signature, header, source and cache key are all unchanged.
  • Procedures that contain bool values can now scalarize. Previously a procedure had to be all float64.

  • A single select is if-converted and vectorized, so it runs at the speed of fmax and beats NumPy by about 30%. Lowering fuses the whole piecewise expression into one loop with no bool temporaries.
  • Finding: gcc keeps a nested ternary on random data as branches, which is about 9× slower. This is a C-compiler scheduling effect, not a correctness issue. The fix is cheap: an arithmetic rewrite of select(x>c, c, x) into fmin/fmax. I'd like to add it as a follow-up item rather than widen this PR.
  • First-call build time (render plus compile) is 17–21 ms for every variant. select adds no measurable build cost.

Deviations from the plan

  • cast to bool is built as x != 0 instead of a C cast. A C (uint8_t) cast would truncate 0.5 to 0.
  • Scalarization is now allowed for procedures containing bool. The plan did not say this explicitly, but it is needed for select-heavy solver code.
  • The structural multi-seed JVP covers select. copysign and cast use the existing unrolled fallback.
