Summary

Where things stand

  • The compiler grew for good reasons, and it also absorbed domain code. The general additions (scan/while with multi-seed AD, function templates and pytrees, predicates/select/cast, run-time indexing, the split program-pass pipeline) belong in the core. About 1.4k lines of linear-algebra support (8 ExprOps, their verify, AD, sparsity and lowering rules) do not. They sit in six core files so that linalg, solvers/ipm and one integrator can use them.
  • The core already depends on the solvers, inverted. This was true on main too. passes/lowering, codegen/aot, codegen/jit and codegen/toolchain import scaly.solvers.* and read QP/NLP descriptor fields by name. codegen/c.py imports the CasADi adapter.
  • Nothing below lowering needs domain knowledge. Every domain op lowers to generic program ops, so the program dialect, the pass pipeline and the C renderer are already clean. The blocker to moving ops out is on the expression side: ExprOp is a closed StrEnum, and AD, sparsity and constant folding are if-chains. Only the @lowers registry is open.
  • The IPM is not wired into sc.solver. The only bridge is examples/qp_solvers/generated_piqp.py, which imports six private helpers from solvers/qp.py and solvers/nlp.py. Two case studies and two integration tests reach it through sys.path.
  • The examples hold about 2.5k lines of real library code. This includes a generated TinyMPC ADMM solver, an AL-iLQR (ALTRO) solver, the SCvx/PTR loop, a differentiable-MPC implicit rule, Fatrop and acados drop-ins, quaternion algebra, MLP builders (four copies across examples, benchmarks and tests), and more than 20 hand-written RK4 copies.

Recommendation

Keep a core of about 15k lines: ir, function, ad, passes, codegen (C only), plus a new public extension module scaly.ext. Move everything else into 17 new workspace distributions (beside the three vendored solver plugins) arranged in six tiers, all depending on the core through scaly.ext and on each other only along a declared, acyclic graph. The order of work is: invert the solver edges first, open the op vocabulary second, move linalg third, then split the rest in dependency order.

2 · The core

What the compiler must own, and nothing more

The test for membership is: can a user write a differentiable numerical algorithm over tensors, with loops, and get C out of it, without the item? If a feature is required for that, or is required by every domain package, it is core. If it can be expressed through the extension interface without loss, it is not.

  • Linear algebra leaves the core vocabulary. These ops have one consumer family each: LU exists for integrators.implicit; SEGMENT_MAX for solvers/ipm/ruiz.py; RAGGED_* and SPARSE_LDL* for SparseLDL. The docstring of SPARSE_LDL states it equals SparseLDL(schedule="scan") bit for bit, so the fused ops are performance kernels of a composite that already exists. Registered as extension ops they keep their speed, and the core stops carrying the tables, the tiling constants and the AD refusal messages that name linalg.
  • The indexing family consolidates from 9 ops to 5. Since Tier 1 fixed scatter to accumulate, scatter is segment_sum; one SEGMENT_REDUCE with a combiner covers sum, max and min. index_add/index_set are put_add/put with a constant index (passes/affine.py already recovers the structure), and no domain module calls them. 5 · Extension API

scaly.ext: what packages are allowed to touch

Independent upgrades need one versioned surface between the core and everything else. Today that surface is implicit: private attributes, closed enums, and import-time side effects. The existing solver protocol (SOLVER_PLUGIN_PROTOCOL_VERSION, now 7) is the model to generalize.

  1. Op registry. ExprOp becomes a string-keyed registry. The builtins register through the same path, so there is one mechanism. Each op carries its builder type rule, verify rule, NumPy fold, JVP, multi-seed JVP (default: stack per-seed JVPs), VJP, sparsity (default: dense), lowering, and trait flags. Registering a name twice is an error, which preserves the hash-consing rule that an IR class and an op identity exist once.
  2. A public lowering context. A documented subset of LowerCtx: allocate a buffer, emit a statement, fresh names (in place of ctx._tmp), output aliasing, the loop and index helpers the linalg rules use today (_blocked_sum, _copy_loop, _lane_loops).
  3. Extern callee protocol. One opaque op, EXTERN_CALL, whose attribute implements dependencies(), extern_sources(), render(ctx), build_requirements() and an optional state blob with a ctypes view. Vendored solvers, and later external kernels (BLAS, METIS), are users of it. Generated solvers need none of it: they are ordinary Functions.
  4. Output adapters. register_adapter(name, header=, extra_source=, entry_prologue=, extra_workspace=) replaces the lang and casadi flags and the --lang/--casadi CLI switches.
  5. Pass slots. Named anchors in the explicit pipeline (insert_after("fuse_elementwise", pass)), so ordering stays explicit, which was the reason register_pass was removed.
  6. Option namespaces. sc.options(linalg=dict(dense_unroll=8)); each namespace declares whether it affects AD helper naming.
  7. Library-author Function API. Public from_exprs, lift and template tokens, plus the SymbolicValue leaf protocol, so SparseMatrix and similar values can cross Function boundaries.
  8. Cache identity. The JIT cache key includes the versions of the extensions whose rules contributed to a render, so upgrading scaly-linalg invalidates exactly the code it generated.
@dataclass(frozen=True)
class OpDef:
  name: str                                   # "linalg.cholesky"
  arity: int | None
  infer: Callable[..., TensorType]
  verify: Callable[[Expr], str | None]
  fold: Callable[..., np.ndarray] | None
  jvp: JvpRule | None                         # None: not differentiable, raise if seeded
  jvp_many: JvpManyRule | None                # default: stacked single-seed jvp
  vjp: VjpRule | None
  sparsity: SparsityRule | None               # default: dense in every argument
  lower: LowerRule
  traits: frozenset[str] = frozenset()        # "elementwise", "runtime_index", "update", "exact_reads", "expensive"

scaly.ext.register_op(OpDef(...), api=EXT_API_VERSION)

A function-level route already works without any of this: custom_derivative(fn, jvp=, vjp=, sparsity=), which linalg.dense, interp.spline and integrators.implicit use for their implicit derivatives. The op registry is only for kernels that must lower as fused code.

6 · Packages

Seventeen new packages, plus the three solver plugins

A package may depend on the core and on packages in lower tiers only, along the edges listed in each card. The set is designed for how the work will grow (multistage KKT, estimation, sensitivities, embedded targets), not for how the directories look today. Three of today's boundaries move: transcription leaves integrators for scaly-ocp, Newton loops leave integrators and interp for scaly-nonlinear, and polytopes leave mpc for scaly-sets.

8 · Packaging

One workspace, separate distributions

  • Layout. The repository is already a uv workspace with plugins/* as members. Extend it: packages/scaly-linalg, packages/scaly-opt and so on, each with src/, tests/, examples/, its own version and changelog. The vendored plugins stay under plugins/.
  • Import names. Separate top-level names (scaly_linalg, scaly_opt), as scaly_piqp already does. A scaly.linalg namespace would need pkgutil path extension over a regular package, which is fragile with editable installs and risks the one failure the codebase guards hardest: an IR class loaded under two module paths.
  • Compatibility. The core publishes EXT_API_VERSION; each package declares the range it supports and checks it at import, as solver plugins do with protocol 7. That is what lets scaly-ipm change weekly while scaly stays put.
  • Enforcement. Extend tests/test_import_layering.py with a package table: the core may import no scaly_*; each package's imports must match the dependencies in its pyproject.toml; the graph must be acyclic. The existing per-module layer table stays inside the core.
  • Tests. Split the node-ID baseline per package; Maros–Meszaros data moves with scaly-ipm; the C snapshots stay with the core and are the oracle for every refactor in the plan below.
  • Housekeeping. Remove the untracked src/scaly/ir/.ipynb_checkpoints/ copy of expr.py, plugins/alloy-* (≈230 MB), mymodule.py (still imports alloy), pla/, generated/; move typing_playground out of testpaths. Add integrators/ and mpc/ to the package map in docs/dev/codebase.md. Consider moving internal/ reports and perf data (571k lines) out of the main history.
9 · Migration

Seven phases, each gated

0

Safety and housekeeping

Make SOLVER_CALL raise on a seeded path and return a dense (not empty) sparsity mask. Remove the stray files. Fix the codebase map.

Gate: the full suite passes, with a new test that differentiating through a solver raises.
1

Invert the solver edges

Introduce EXTERN_CALL and the extern-callee protocol. Move codegen/solver.py, stats, paths and registry into scaly.solvers while still in-tree. Replace the lang/casadi flags with the adapter registry.

Gate: no module under ir, ad, function, passes or codegen imports solvers, cpp or casadi; C snapshots are byte-identical; solver-marked tests pass.
2

Open the vocabulary

Op registry with builtins registered through it; table-driven AD, sparsity, folding and verification; public LowerCtx; op traits; option namespaces; scaly.ext with the library-author Function API; extension versions in the cache key.

Gate: byte-identical C snapshots, unchanged benchmark medians, and an out-of-tree toy op (defined in a test) that differentiates, lowers and compiles.
3

Move linear algebra out

The 8 ops, their rules and linalg/* become scaly-linalg, with tests/linalg and the ragged/sparse-LDL tests.

Gate: the core suite runs with scaly-linalg uninstalled; with it installed, snapshots and IPM perf are unchanged.
4

Split in dependency order

scaly-opt (plugins retarget) → scaly-ipm (absorbs generated_piqp, registers backend="scaly") → scaly-nonlinear → scaly-integrators, scaly-interp → scaly-ocp, scaly-sets → scaly-mpc; scaly-viz, scaly-export, scaly-nn in parallel.

Gate per package: the package-level layering test passes, its suite runs in isolation, and no example imports a private name.
5

Promote the example machinery

TinyMPC, AL-iLQR, iLQR, SCvx and the diffmpc rule into scaly-trajopt, with linalg.stagewise replacing the Riccati copies; drop-ins into scaly-export; geometry; scaly-bench and scaly-testing. Replace hand-written RK4 and Newton loops.

Gate: case-study numbers reproduce within their recorded tolerances.
6

Optional consolidation

Collapse the indexing family (9 ops to 5) and fold scatter into SEGMENT_REDUCE.

Gate: snapshots may change only where the consolidated ops appear; differential tests against NumPy pass.
