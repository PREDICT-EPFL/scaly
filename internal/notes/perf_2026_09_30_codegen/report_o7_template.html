O7: a transpose fused into the gather that reads it

Step 7 of the generated-code speed plan · todo C-202, the first step of C-77 · branch perf/codegen-speed · 30 Sep 2026 · Apple M3 Max, Apple clang 21, the JIT's flags

Summary. A sparse Hessian is recovered by transposing a seed-major product and gathering its nonzeros (gather(transpose(jvp_many(...))), C-77's description). The transpose lowered to a loop nest, which fusion cannot inline, so every entry was computed and stored before the gather read a subset: in the race-car Hessian at N = 40, 984 entries, each with two table reads and four products, for 527 used. A transpose is now one flat loop over its output, which fusion inlines into its one consumer.

  • Speed: race_cars_40 1.035× faster (9.94 → 9.60 µs by a direct A/B), race_cars_200 1.02×; the other kernels whose C changed (chain, npmpc, unbumpercars, riccati, the MLP Jacobian) within ±2%.
  • The rule that makes it safe: a transpose that only moves data is not inlined into a consumer that reads it through a table: the permutation's divisions would run per element. Without the rule race_cars_jac_40 was 1.05× slower (5.98 → 6.28 µs, its gather reads 86% of a plain copy).
  • Unfused transposes are split back by delinearize_loops into a loop per output axis without divisions, the same loops as before under new names.
  • Tests: 4 459 passed, 57 skipped, 5 xfailed (6 new). Four mutants, four killed. Snapshots regenerated where a transpose's loop names moved.
  • Undo: git revert the commit “Codegen speed O7”.

What changed

  • passes/lowering.py: _lower_transpose emits out[t] = src[Σ o_i(t) · stride_{axes[i]}] over one loop, the coordinates by _coord_p.
  • passes/program/fuse_elementwise.py: _reads_through_a_table; a producer whose value is a single load is not inlined where its consumer's index loads.
  • docs/how_it_works/lowering.md: the transpose's form and the rule.
- for (d0 < 246) for (d1 < 4) { v4 = d0 + 246 d1; ...; s0[4 d0 + d1] = (s2[v4] + ...); }   // 984 entries
- for (i < 527) res[0][i] = s0[k43[i]];
+ for (i < 527) { v = k43[i]; v4 = v / 4 + 246 (v % 4); ...; res[0][i] = (s2[v4] + ...); }   // 527 entries
