O2: dot products and sums in partial sums

Step 2 of the generated-code speed plan · todo C-196 · branch perf/codegen-speed · 30 Sep 2026 · Apple M3 Max, Apple clang 21, the JIT's flags

Summary. Every reduction the matrix products and sum lowered to was one chain of dependent adds, which runs at the latency of one multiply-add per step on a core that retires eight a cycle. -fassociative-math showed the headroom; the generated code now takes it itself, in an order it fixes, without the compiler's license to reorder.

  • Speed (kernels whose C changed): matvec_256 2.80× faster (18.1 → 6.5 µs), mlp_big_fwd 2.16×, unbumpercars 1.55× (736 → 475 µs), npmpc 1.32× (19.5 → 14.8 µs), mlp_small_jac 1.13×, elementwise_1e5 1.06×, the sparse IPM 1.04×. The IPM kernels take the same iterations to the same solutions.
  • Against -fassociative-math: unbumpercars 0.645 against 0.585, npmpc 0.759 against 0.710, mlp_big_fwd 0.463 against 0.425. The rest of that headroom is in the dense factorizations' tiles (chol_solve_200 0.64, ipm_cvxqp1_dense 0.83 under the flag, unchanged here).
  • A latent bug fixed, exposed by the first strided loop to carry a division: delinearize_loops evaluated a loop's indices at its trip numbers, not its variable's values. The generated IPM's objective came out 4.98 instead of 7.69 in the embedded-QP case study test.
  • Tests: 4 426 passed, 57 skipped, 5 xfailed (28 new). Nine mutants, nine killed (two after strengthening a test). Snapshots wide.c and workspace.c regenerated.
  • Undo: git revert the commit “Codegen speed O2”.

What changed

  • sum and dot (passes/lowering.py, _reduce_into): from eight elements, four partial sums, element k into partial k % 4, the elements past the last whole block into the first, combined as (p0 + p1) + (p2 + p3). Every read of the terms sits in one statement (a loop run once, as the max/min reduction has done since C-137), so an elementwise producer fuses into the sum. A private result is the first partial sum, so it is live from the start as a sequential accumulator was and the workspace packer does not park it in a slot its terms free; an output is not, since the ABI's buffers are memory the compiler must assume the terms alias.
  • a @ x (_lower_matvec_blocked): from eight columns, four rows per pass, each row in four partial sums, sixteen chains the C compiler pairs into NEON lanes, the sums in private scalars and each output stored once; the rows left over run one at a time the same way. vec @ mat and mat @ mat already put the reduction outermost and vectorize over independent outputs, and are unchanged.
  • _blocked_sum takes a lane count and a first slot, and folds a static tail bound in Python (fusion needs a constant trip count). The dense factorizations that use it keep their four lanes.
  • fuse_elementwise: an expensive (libm) producer fuses when its element loads run no more often in all than it has elements, in place of exactly one textual load. buf * buf is still refused (twice per element); four partial sums reading each element once are not.
  • delinearize_loops: indices evaluated at k = 0, s, 2s, ….
  • docs/how_it_works/lowering.md: the summation order.

Four rows by four lanes is never far from the best and never bad; eight rows fail when there are fewer rows, one row fails when the row is short (the 100×7 column is why seven columns and fewer keep today's form). For a single sum or dot product, eight lanes were faster than four on long vectors (dot 0.23 against 0.64 of one chain at n = 256), but eight lanes took the sparse IPM off PIQP's path on QBEACONF: the rounding decides that problem's path, and with eight or sixteen lanes it stalls at the iteration limit where two and four lanes, and the base, solve it in 19–21 iterations. The traces of four and eight lanes both leave the base's at 1e-15 on the first iteration and diverge a thousandfold every few, so it is the problem's sensitivity, not a wrong sum; four lanes keep the whole IPM gate (600 tests) and match the codebase's other blocked reductions. Eight lanes are recorded as a follow-up that needs that gate settled first.
