Where scaly stands

A compiler that now reaches algorithms

  • The compiler core (two verified dialects, pattern rewriting, eleven program passes, loop-preserving lowering) is mature and has carried three tiers of new primitives without structural change.
  • Differentiation is the strongest layer: forward and reverse through calls, vmap, scan and while_loop, colored sparse Jacobians and Hessians that keep stage loops, and implicit rules two levels deep.
  • Whole algorithms now compile to one C function: sparse LDLᵀ, dense Cholesky/LDLᵀ/LU, PIQP's full IPM (decision traces matching PIQP), TinyMPC's ADMM, adaptive and implicit Runge–Kutta.
  • The domain layer is thin: integrators exist, scaly.mpc is planned and signed off, estimation, identification and data-driven control live only in examples.
  • The clearest gaps are derivatives through solver calls (silently zero today), structure-exploiting multistage KKT solves, conic constraints, lazy conditionals, interpolants, and an embedded (float32, cross-compiled) target.

L0

Target, build & deployment

How a scaly Function becomes machine code and reaches a caller: rendering, compiling, loading and the C interface.

Emission

  • Standalone scalar C from the program dialect (codegen/c.py); no lowering policy in the renderer
  • C++ header: a Buffer template and a namespace per function (lang="cpp")
  • CasADi 3.8 compatible symbols: query functions, CSC sparsity, so generated code drops into CasADi-style consumers
  • Caller-owned workspace; stable pointer ABI with status codes and mangling

Build & load

  • JIT: render, compile, cache under ~/.cache/scaly, dlopen, ctypes dispatch; per-thread workspace reuse, about 3 µs trivial-call floor
  • AOT: write_module and the scaly_codegen module:fn CLI
  • Toolchain discovery (SCALY_CC, CC); -O2 -march=native -fno-math-errno, -ftree-vectorize on GCC < 12

Platforms & data

  • Linux and macOS (Apple clang); Windows not supported
  • float64 across the ABI; int64 and bool carried as doubles
  • Solver wrapper framing around plugin-rendered bodies; versioned solver-statistics ABI

Candidate additions

7 at this level

Windows support

MBacklog · R-38

SolvesIndustrial and teaching users on Windows; CI parity for a public release.

AnalysisThe core JIT needs MSVC or clang-cl discovery and a DLL loader path. Two real obstacles: MSVC has no C99 variable-length arrays, which the dense kernels emit (double s0[n], see C-117), and the vendored IPOPT/MUMPS/METIS builds. Doing C-117's move of stack arrays into the workspace first removes the first obstacle. clang-cl is the lower-risk toolchain.

JIT cache key without lowering

SBacklog · C-115

SolvesEvery new process re-runs lowering and passes (2.6 s for an unrolled MPC N = 20 factor) before it finds the cached library.

AnalysisKey on a structural hash of the graph (callees, custom rules, attributes, options), the scaly version and compiler flags. The review of 2026-09-27 found 13 AD caches that miss the options and a key that misses the compiler, so this should be done together with a single cache-key authority. Risk: a key that misses an input returns stale code silently; a debug mode that re-lowers and compares would bound that.

Embedded target profile

LNew

SolvesMicrocontroller MPC and estimation (the TinyMPC and QOCOGEN benchmarks target MCUs; lever L6 in the case-study plan), certification-friendly code.

AnalysisThree parts: float32 generation (the DType table and BACKEND_SUPPORT already model it, but the ABI spells casadi_real as double and constant folding runs in float64); a target description for cross-compiling (arm-none-eabi-gcc, no -march=native, optional libm-free builds); and static-only memory with a reported worst-case stack. Tolerances inside the generated IPM and refinement must become dtype-aware. This is the prerequisite for Tier 6's platform selector.

Parallel mapped loops

MNew

SolvesScenario-tree MPC, sampling-based MPC, batched simulation, multi-start, dataset-wide model fitting.

AnalysisAdd a PARALLEL range kind for vmap whose body has no cross-lane writes, rendered as an OpenMP pragma behind a flag. The program dialect already records loop intent (RangeKind, after tinygrad's AxisType), so this is mostly legality checking and reductions across lanes. Embedded builds keep the serial loop; the CasADi parallel_map mirror notes the serial limitation today.

Batched Python dispatch

SNew

SolvesTiny problems pay a 3–12 µs Python call against 1–5 µs of C (C-132); Monte Carlo, grid evaluation, closed-loop sims from Python.

AnalysisOne ctypes call that loops over a leading batch axis in a generated C wrapper. Cheap, and it removes the call floor from every benchmark comparison that runs from Python.

Deployment wrappers

MNew

SolvesGetting generated controllers into Simulink (S-function), FMI 2/3 co-simulation (FMU), ROS 2 nodes, Rust or Julia callers.

AnalysisEach wrapper is a template over the existing C header, and the CasADi-compatible query functions already give sizes and sparsity. Effort is per wrapper (S each), M for a maintained set with tests. Worth doing only for targets with a named user.

GPU backends

XLBacklog · D-36

SolvesMassive sampling (MPPI), batched OCPs, learning with the solver in the loop.

AnalysisDeviceSpec reserves cuda, opencl and metal but nothing lowers to them. The scalar-C design, while loops and sparse factorizations map poorly to GPUs; a credible first milestone is a vmap of a scalar body as one kernel. Define the milestone (D-36) before any code.

L1

IR & compiler passes

The two dialects, their verifiers and text form, and the transformations between and within them.

Dialects

  • Expression dialect: hash-consed typed tensors with sparsity metadata; about 70 ExprOps
  • Program dialect: buffers, loops with RangeKind, statements
  • Explicit verifiers from one Rule/Spec table machinery; one VerifyError
  • Stable, diffable assembly text for both dialects

Rewriting

  • One pattern matcher and iterative rewrite driver for both dialects (Pattern, rewrite)
  • Expression passes: simplify, constant folding, cse
  • Shared arithmetic identities applied to graphs, scalarized code and loop bodies

Lowering & program passes

  • Per-op lowering rules; hints scalar/block/opaque/auto; unroll thresholds as options
  • In-place carry proofs for fixed and run-time indices
  • Hoisting, scalarization, elementwise fusion (also into max/min reductions), scatter-sum combining, arithmetic folding, unit-loop removal, delinearization, workspace packing, store coalescing, scheduling
  • Affine index maps instead of materialized index tables

7 at this level

Structural refactor from the 2026-09-27 review

MNew

SolvesDrift and silent slow paths: each elementwise derivative is spelled three times, and the multi-seed table lacks about 12 ops, which makes jvp_many re-run the expression once per seed without an error.

AnalysisOne table of partials per elementwise op from which forward, multi-seed and reverse follow; split passes/lowering.py (2 300 lines) into a package with the alias analysis in its own module; one name-reservation authority. This lowers the cost of every op added in L2 and should precede them.

Generation-time reduction

LBacklog · C-111

SolvesAbout 1.2 ms per scalar operation to generate unrolled code; it caps dense_unroll and sparse_unroll, and limits large AC-OPF instances (case study E6).

AnalysisMostly in match.rewrite, fuse_elementwise, fold_arith and pack_workspace, linear in size. Candidates: memoize lowering per callee signature, batch rewrites per op bucket, and skip passes whose preconditions a cheap scan rules out. Profile first; halving it doubles the unroll thresholds.

Compile-time reduction

SBacklog · C-116

Solvesgcc spends 2.5 s on an unrolled MPC N = 20 factor because about 1 000 one-element buffers stay live until the final stores.

AnalysisStore each result into res when computed; halves compile time with no run-time change. Needs an ABI rule on whether res may alias arg, which should be written into the generated-interface page.

Register accumulators and explicit lanes

MBacklog · C-79, C-89, C-90

SolvesReductions run 6–7× slower than NumPy at n = 10⁶; dense products dominate TinyMPC at 16–32 inputs (0.80× the library); nested ternaries stay branches.

AnalysisKeep reduction accumulators in registers (scalarize must learn ASSIGN), rewrite select(x > c, c, x) to fmin/fmax, and add explicit SIMD lanes on mapped ranges after tinygrad's shift_to. The register-tiled Cholesky (C-136) shows the payoff pattern.

Loop fusion and memory-aware CSE

MBacklog · C-96, C-54

SolvesAdjacent zeroing, copy, scale and scatter-add loops in derivative code; redundant program-level work after lowering.

AnalysisFusion legality for the loops scaly emits is the affine-dialect textbook case (MLIR). Deferred until a measured workload needs it, which the MPC layer's Lagrangian Hessians may provide.

Schedule selector with a cost model

LPlanned · Tier 6

SolvesGlobal thresholds (dense_unroll=8, sparse_unroll=1000) choose unroll, loop or gather code for every pattern and target alike.

AnalysisA target description plus a selector over lowering options, optionally tuned by measurement and cached per (pattern, size, target). Most valuable once the embedded profile exists, since MCU and desktop optima differ.

Checked build mode

SNew

SolvesWrong numbers with no error (C-125 was one); NaN origin hunting inside long generated procedures.

AnalysisRender bounds assertions and per-statement non-finite checks that report the originating Expr name, behind an option. This is not an interpreter fallback, so it respects rule 7 (generated C is the only semantics).

Interpolants and lookup tables

MNew

SolvesRace-track centrelines, tyre and aerodynamic maps, efficiency maps in HVAC and building models, table-based plant models; CasADi's interpolant is one of its most used features.

AnalysisLinear and B-spline interpolation on fixed 1-D/2-D grids with coefficients as constants or inputs. Lazy conditionals: cond and switch

MNew

SolvesPiecewise models with expensive branches, mode-dependent (hybrid) dynamics, and NaN-safe branching: where(x > 0, sqrt(x), 0) evaluates both sides and poisons the derivative.

AnalysisA structural op with Function branches, lowered to if/switch. Forward and reverse rules are the conditional of the branch derivatives; sparsity is the union. The loop-carry proofs and vmap need a rule (per-lane branches become a select of both). This is the most requested construct missing from JAX-like tools that compile to C.

SNew

L3

Functions & structured control flow

The unit of composition, and the constructs that keep repetition and iteration as loops in the generated code.

Functions

  • @sc.function: one argument per parameter; typed trees L, G, S; output= optional
  • Templates with shape holes: one ConcreteFunction per argument signature with a deterministic C name (f__3x4)
  • First-class call nodes: composition stays a call in C
  • Sparse matrices as arguments and results (sc.S(name, pattern))
  • Options context (sc.options); PyTorch state-dict reader without torch

Repetition & iteration

  • vmap: one loop, C size constant in the length; mapping by (outer, start, stride)
  • scan: ping-pong carries, step number, negative stride, stacked outputs
  • while_loop: static max_iter, loop-invariant params, step number, differentiable
  • In-place carry updates proven at the loop

Extension points

  • custom_derivative(fn, jvp=, vjp=, sparsity=), honoured through calls, vmap, loops and multi-seed forward mode
  • Lowering hints per Function

L4

Differentiation & sparsity

Derivatives as ordinary graphs, structural sparsity, and the coloring that turns them into compressed Jacobians and Hessians.

AD modes

  • jvp, jvp_many (multi-seed), vjp, vjp_many, entirely inside the expression dialect
  • Typed derivative requests (sc.factory): gradient, jacobian, hessian, lagrangian_hessian, forward, adjoint
  • Derivatives are Functions: closed under composition, to any order
  • Derivatives with respect to expressions that are not inputs (slices of a carry)

Through structure

  • One loop per stage survives colored second-order differentiation of vmap
  • scan: trajectory-storing reverse mode, one backward scan per forward scan
  • while_loop: forward as a while loop, reverse as a masked backward scan; max_trajectory memory guard
  • Implicit rules two levels deep: sparse LDLᵀ solves, LU solves, implicit Runge–Kutta, adaptive steps held

Sparsity

  • Structural patterns through calls, maps, loops and factorizations (elimination subtrees)
  • Column and star coloring; structured VMAP Jacobians
  • sparse_jacobian, sparse_hessian, sparse_lagrangian_hessian (upper triangle)
  • Non-smooth conventions split/first/error; finite-difference reference

Stop differentiating solver calls to zero

SNew · correctness

SolvesToday jvp and vjp through a SOLVER_CALL return zeros with no error (ad/forward.py, ad/reverse.py), so a gradient through an embedded MPC is silently wrong.

AnalysisRaise, as rule 7 (no silent fallbacks) asks, until the next item lands. A few lines plus a test.

Sensitivities through solver calls

LNew

SolvesDifferentiable MPC and learning MPC weights (case study E5), bilevel design, policy gradients through a controller, tangential predictors for real-time iteration, dx*/dp for parametric analysis.

AnalysisThe implicit function theorem on the KKT conditions at the returned primal-dual point, under strict complementarity and LICQ. For the generated IPM the KKT factor already exists inside the graph and SparseLDL's implicit rules can be reused (M). Degenerate points need a documented convention (one-sided derivatives, or a smoothed barrier at the final μ as in DiffMPC).

MNew

SolvesLong-horizon single shooting, long simulations in parameter estimation, while loops whose trajectories exceed max_trajectory and are refused today.

AnalysisBinomial checkpointing (Revolve) for scan: store every k-th carry and recompute segments in the backward pass. Trades a bounded recomputation factor for memory; the policy can be an option next to max_trajectory.

Backward pass for the steps taken

SBacklog · C-92

SolvesThe reverse sweep of a while_loop runs all max_iter masked steps even when the loop stopped early.

Interval and McCormick transforms

LNew

AnalysisA graph transformation like AD: each op gets an interval (or McCormick relaxation) rule and the result is another Function. Fits scaly's architecture well and has no counterpart in CasADi; start with intervals (M), relaxations later.

L5

Linear algebra

Sparse and dense factorizations written once in Python and generated per pattern, with implicit derivatives.

Sparse

  • SparseMatrix: static CSC pattern, Expr values; union add, Hadamard, row/column scaling, products (pattern at build time), blocks, triangles, SciPy interop
  • Symbolic analysis: natural, RCM, MMD and auto orderings; elimination tree; pattern of L; supernode chunks
  • SparseLDL: scan, unroll and loop schedules (one loop nest, chunks of up to eight columns); solve op; fixed or adaptive refinement; inertia(), health()

Dense

  • cholesky by 4×4 register tiles; ldl (no pivoting); lu with partial pivoting; triangular solves
  • cho_solve, ldl_solve, lu_solve, solve(assume="pos"|"sym"|"gen")
  • Straight-line code up to order 8; derivatives in both modes to second order

Measured

  • Sparse factorization at 1.0–1.4× the time of an up-looking C LDLᵀ before C-135's loop nest, then 1.5–2.2× faster again
  • Dense Cholesky 12 GFMA/s at n = 300 on an M3 after tiling (3.3× the old kernel)

L6

Dynamics & integrators

scaly.integrators: continuous-time models turned into discrete maps with the model's own signature.

Explicit & adaptive

  • Butcher tableaus with order conditions checked by B-series over rooted trees
  • Ten named explicit methods (Euler to RK4, 3/8 rule, Bogacki–Shampine, Dormand–Prince); substeps unrolled up to four, a scan beyond; dt folded or an input
  • si.adaptive: DOPRI5 or BS32, RMS error control in a while_loop, derivatives with the step sequence held
  • si.symplectic: Störmer–Verlet, symplectic Euler

Implicit

  • Gauss–Legendre, Radau IIA, Lobatto IIIA/IIIC for any number of stages; backward Euler, midpoint, trapezoid, SDIRK2/3
  • Newton fixed or to tolerance, full or simplified; RADAU5's eigen-split of I − hA⊗J
  • Implicit-function-theorem derivatives at the stages, exact to second order

Linear & helpers

  • si.zoh, si.foh (SciPy expm, numeric), si.linearize as generated code
  • Gauss, Radau and Lobatto nodes and Lagrange integrals
  • I4 (linear, adaptive, symplectic) is in the working tree, not yet committed

Suggested order

A sequencing across levels, weighing reach against effort and what unblocks what.

  1. Close the silent-wrong paths

    Raise on AD through SOLVER_CALL, fix the bugs reproduced in the 2026-09-27 review, and adopt one partials table so missing multi-seed rules fail loudly. All S–M, all correctness.

  2. Finish integrators and scaly.mpc as signed off

    I5 then M1–M4. It absorbs 20+ duplicated RK4 copies and five horizon-stacking variants, and gives every later control feature a home.

  3. Tier 4, then the multistage KKT solve

    backend="scaly" makes the generated IPM usable; the Riccati-structured factorization is the performance story for long-horizon MPC and the gate against HPIPM/FATROP-class solvers.

  4. Small primitives with wide reach

    Interpolants, lazy cond, stable special functions, the PRNG, Rosenbrock methods. Each is S–M and each unlocks several applications at once.

  5. Sensitivities through solvers

    Reuses the implicit-rule machinery already proven on SparseLDL and implicit RK; unlocks differentiable MPC (E5), learning-based tuning and tangential predictors for RTI.

  6. The embedded profile

    float32, cross-compilation and static memory, measured on an MCU. This is the claim that separates generated algorithms from vendored libraries.

  7. Estimation, identification and data-driven control

    Mostly packaging of algorithms already in examples, plus the least-squares solver and QR. Close to the lab's research and cheap relative to its value.
