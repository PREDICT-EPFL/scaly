Tier 2 · PR 8 report

T2-8 · ragged loops and the second optimization round of the sparse LDLᵀ (C-109) · branch claude/tier2-sparse · 26 Sep 2026

Summary. Two new expression ops run loops whose length is set at run time over fixed index maps:

  • ragged_add: for each group and each p in [lo, hi), base[dst_map[p]] += src[src_map[p]] · scale[g].
  • ragged_dot: one dot product per range.

The two ops are closed under differentiation: each one's derivatives in forward and reverse mode are again one of them.

The factorization rewritten on them. The sparse LDLᵀ update is now, for each column k in row j, one run over the contiguous part of column k, the same loop the C reference has. Both triangular sweeps are single-range ops, with no padding at all.

What changed.

  • Every test matrix now factors within 1.0–1.4× of the C baseline; before, 1.3–2.6×. The random QPs are now inside the 2× gate.
  • Solves run at 0.5–1.6×. On the QPs they are twice as fast as the C baseline.
  • Tables are the size of K and L, not of the work.
  • Generation at nnz(L) = 153 k with 25 M multiply-adds went from 17.9 s to 2.5 s.

Suite: 1 365 passed, 88 skipped; the same four VM-only failures. ruff, ty and the docs build are clean. Mutation checks: 9 of 9 killed, one only after a test was added.

1. What was built

PieceDetails
Ops
  • ragged_add(base, src, lo, hi, scale, dst_map=, src_map=) and ragged_dot(a, b, lo, hi, a_map=, b_map=) (internal, ir/expr.py).
  • The maps are fixed static const tables; None is the identity.
  • The ops are unchecked by contract: library code builds the ranges from its own tables.
Lowering
  • ragged_add: an outer loop over groups and an inner loop with run-time bounds [lo[g], hi[g]). As a link of an in-place chain it writes the carry directly.
  • ragged_dot: four partial sums per range, as the dense dot products use.
Derivatives
  • Forward mode: the same op with one operand replaced by its tangent at a time.
  • Reverse mode: src̄ is a ragged_add with the maps swapped; scalē is a ragged_dot; ā and b̄ are ragged_adds.
  • Multi-seed forward mode stacks one tangent per seed (up to 64 seeds; beyond that it falls back to one seed at a time).
In-place proof
  • A ragged_add in the chain is an update whose write set is its mapped ranges. As a reader, its source (or a ragged_dot's operands) contributes the mapped ranges read.
  • Ranges stay ranges (_Ragged). Overlap is tested first on per-step intervals, using the range bounds or the map's extremes, and entry by entry only where the intervals meet.
  • For the factorization, reads of L and writes to the work area never meet.
Sparse LDLᵀ
  • Factor step: u2 = ragged_add(u1, carry, r_lo, r_hi, −D[k]·L[j,k], dst_map = w_off + l_rows).
  • The column of L is a single-range ragged_add from the work area.
  • Per step, the tables are the matrix column (a), the row of L (g groups; a padded group is an empty range) and the clear list (c).
  • The segment DP prices exactly these widths.
  • The sweeps are one ragged_add (forward) or one ragged_dot (backward) per column, on a carry of size n.
Generation cost
  • The symbolic analysis builds its update-lane tables lazily. Only the old padded path and statistics used them.
  • The lane limit rises to 500 M, since the lanes no longer become tables.
  • new_const_index keeps one table per content in a procedure: the same l_rows map was being emitted twice.

The generated factor step now reads like the reference:

for (g = 0; g < 9; ++g)                                    /* each column k in row j */
  for (p = r_lo[g]; p < r_hi[g]; ++p)                       /* column k from row j down */
    c[k6[p]] = c[k6[p]] + c[p] * s[g];                       /* w[l_rows[p]] -= L[p] D[k] L[j,k] */
...
for (p = col[0]; p < col[1]; ++p) c[p] = c[p] + c[k6[p]] * inv;   /* L[:,j] = w[rows] / D[j] */

2. Tests

tests/integration/test_ragged.py has 15 tests; test_sparse_ldl.py gains 6 (45 → 51 with parametrization).

  • Values. Checked against NumPy with an empty group and overlapping groups, with maps and with identity maps.
  • Derivatives. With respect to base, source and scale:
    • gradient against finite differences;
    • strict multi-seed Jacobian equal to the gradient;
    • Hessian against finite differences of the gradient;
    • single-seed jvp equal to gradient · direction.
  • Sparsity and code shape. The sparsity is conservative, and the inner loop has run-time bounds.
  • Interval test. It agrees with enumeration on six cases: adjacent ranges, overlapping ranges, meeting intervals with disjoint entries, a far mapped range, a near mapped range, and an empty range.
  • In place. A carry updated by ragged runs runs in place when the step reads x and writes y, keeps two slots when it reads what it writes, and matches both the two-slot loop and NumPy.
  • Padding. The padded groups of the factorization are empty ranges, and the real ranges sum exactly to the update work (3 matrices × 2 orderings).
  • Existing tests. The whole existing sparse LDLᵀ suite passes unchanged, including in-place-only code, gradients and Hessians.

Mutation checks (9 of 9 killed):

  • maps swapped in the lowering
  • maps swapped in the scale cotangent
  • map bounds from one entry
  • update sign
  • non-empty padded ranges
  • backward sweep without its map
  • forward sweep sign
  • constant-table dedup by length
  • ragged reads not recorded in the proof

The padded-range mutant first survived because the padded groups did no harm (zero weight), only extra work; the new table test catches it.
