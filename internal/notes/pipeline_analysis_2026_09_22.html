1. The pipeline at a glance

Scaly has one direction of travel: a Python-traced, hash-consed expression DAG (the expression dialect), transformed in place by AD and simplification, is lowered once into an explicit loop/buffer IR (the program dialect), optimized by a fixed sequence of eleven passes, verified and rendered to a single C translation unit. There is no interpreter; Python calls, tests and AOT output all run through the same C.

The loop range carries a RangeKind (serial, vector, global, reduce, unroll, …, borrowed from tinygrad’s axis types). Today the lowerer produces only global and reduce; vector is declared but unused, which is the hook C-79 plans to exploit.

3. Lowering: Expr → Program

lower_function(fun) produces a PROGRAM whose last PROC is the entry point. For each Function reached (the root, every call/VMAP callee, every solver oracle) _lower_to_proc:

  1. captures the effective lowering hint (auto | scalar | block | opaque), then normalizes a private copy of the outputs by alternating simplify and cse to a fixed point (at most four rounds), so the user’s graph and the AD graph are untouched;
  2. declares one global buffer per input and per output, and aliases each computed output expression to its output buffer, so the producing rule writes in place (no final copy);
  3. walks the DAG in topological order and dispatches each node to its @lowers rule, which appends statements and records the buffer holding the node’s value (value_buffers[expr.id]);
  4. tags the PROC with scalarize_mode: procedure if every value is float64 and the hint is scalar or auto (never for the entry point under auto), otherwise disabled.

Two features of the initial program matter for everything downstream. First, lowering is one buffer and one loop per expression node: it is deliberately naïve and leaves fusion, scalarization and storage to the passes. Second, the VMAP rule produces FOR { CALL }, and every pass stops at a CALL; this single fact explains most of the remaining performance gap (Section 7).

4. The optimization pipeline

PASS_PIPELINE in passes/program/__init__.py is an explicit tuple; optimize_program runs it once, in order, then verify_program checks the result. Grouped by what they act on:

1 · Structure

  1. hoist_invariant: a VMAP callee with broadcast (stride-0) arguments is split into a _hoist_<pos> prologue called once and a _hoisted_<pos> body taking the prologue’s buffers as extra inputs.

2 · Expansion

  1. scalarize: selected float64 PROCs (and eligible pure callees) are fully expanded to scalar SSA: constant loop indices substituted, per-element value tracking, constant folding, zero/one identities, sharing into typed temporaries, trees elsewhere (temporary at depth 32). Budgets under auto: 4 096 arithmetic ops per PROC, 16 384 program-wide, 65 536 work units.
  2. prune_procedures: drop PROCs made unreachable by expansion.

3 · Loop cleanup

  1. combine_scatter_sums: Σ of single-use zero-filled scatters → one zero-fill + scatter-adds (slice adjoints).
  2. fuse_elementwise: substitute a single-store, single-use producer loop into its consumer’s load; delete the buffer. Refuses to duplicate libm calls under broadcast.
  3. fold_arith: constant-buffer loads → literals; shared arith identities; constant-fill loops → constant buffers.
  4. unroll_unit_loops: erase empty loops, inline one-trip loops.
  5. fold_arith (again): fold what substitution exposed; drop unused buffers.

4 · Storage

  1. pack_workspace: lifetime-pack private buffers into shared slots; slots ≥ 1024 doubles spill into caller w[] (→ SZ_W).
  2. coalesce_stores: adjacent float64 stores → STORE_PAIR (a double2 vector store), alias-safe.

5 · Render prep

  1. prepare_scalar: bound expression depth with typed temporaries (Clang’s bracket limit), sharing only within a statement.

The ordering is deliberate: hoisting must see the loop-shaped callee; scalarization runs before any fusion or slot reuse so that it sees clean buffers; fusion needs canonical loop-shaped producers, so unroll_unit_loops comes after it; store pairing needs the physical aliases that only exist after packing.

5. A worked trace

A pendulum-like multiple-shooting defect, N = 4, run through lower_function with an observer on every pass (every stage below is render_program_assembly of the program handed to the observer of lower_function(f, observe=…)).

@sc.function(sc.G(sc.L("z", 2), sc.L("u", 1), sc.L("znext", 2)), sc.L("defect", ...))
def defect(inputs):
    z, u, znext = inputs
    dz = sc.concat([z[1:], -(z[:1].sin()) + u])
    return z + 0.1 * dz - znext

@sc.function(sc.L("w", 3*N + 2), sc.L("g", ...))
def cons(w):
    zs, us = w[:2*N + 2], w[2*N + 2:]
    return sc.vmap(defect, N, [(zs, 0, 2), (us, 0, 1), (zs, 2, 2)])

5.3 After scalarize: the stage collapses to two stores

The callee qualifies for automatic expansion (float64, small). Constant indices are substituted, 0.1 is folded into the tree, and -sin(z₀) + u is normalized to u − sin(z₀). The seven buffers are gone.

prog.module {

    %v0 = prog.assign prog.load %z[0] : float64 {declare=True}

  }

5.4 Final C

coalesce_stores turned the two adjacent stores into one STORE_PAIR, rendered as a double2 store; prepare_scalar introduced the shared 2·it_g index temporary in the entry.

static inline void defect_raw(const double* z, const double* u, const double* znext, double* defect, double* w) {
  (void)w;
  double v0 = z[0];
  double v1 = z[1];
  *(double2*)(defect) = (double2){((v0 + (0.10000000000000001 * v1)) - znext[0]), ((v1 + (0.10000000000000001 * (u[0] - sin(v0)))) - znext[1])};
}

int cons(const double** arg, double** res, int* iw, double* w, int mem) {
  (void)iw;
  (void)mem;
  if (!arg || !res) return SCALY_ERR_NULL_ABI;
  (void)w;
  if (!arg[0]) return SCALY_ERR_NULL_INPUT;
  if (!res[0]) return SCALY_ERR_NULL_RESULT;
  const double* t0 = arg[0];
  const double* t1 = arg[0] + 10;
  for (long long it_g = 0; it_g < 4; ++it_g) {
    int64_t v0 = (2 * it_g);
    defect_raw((t0 + v0), (t1 + it_g), (t0 + (2 + v0)), (res[0] + (it_g * 2)), NULL);
  }
  return SCALY_SUCCESS;
}

Four things are visible here, and each maps onto a proposal in Section 8:

  • the two defect_fwd…_defect_z_raw callees have identical bodies under different hashed names (proposal N4);
  • defect_fwd_pack_…_raw has no inputs and writes only constants, yet is called four times in a loop and read through 0/1 mask tables k11, k17 (proposals N3, C-78);
  • index arithmetic is flattened then de-linearized with / and % in four-trip loops (proposal N5);
  • the assembly (copy into s1/s2, transpose into s0, masked combine, final permutation gather k23) sits outside the mapped loop because nothing fuses across CALL (C-77).

6. Rendering, ABI, JIT and AOT

  • Renderer (codegen/c.py) makes no decisions: callees are static inline void name_raw(const double* in…, double* out…, double* w), except forward-AD helpers ("_fwd" in the name), which are noinline to dodge an Apple clang 17 miscompile; the entry is the universal pointer ABI int f(const double** arg, double** res, int* iw, double* w, int mem), close to CasADi’s. Local buffers are C arrays; spilled slots are w + offset; aliases are const double* t = arg[k] + off.
  • Vectors: only STORE_PAIR reaches C as a vector (vector_size(16), aligned(8), may_alias); arithmetic is scalar expression trees, left to the C compiler to contract (FMA) and SLP-vectorize.
  • CModule (codegen/aot.py) is lowered once and read by both consumers, so SZ_W in the header and the spill size in the source cannot disagree. Solver-bearing modules splice the plugin’s render_wrapper body with Scaly-owned stats storage.
  • JIT (codegen/jit.py): SHA-256 over cache version, ABI signature, name, source and flags; cc -O2 -march=native -fno-math-errno -fPIC -shared … -lm; dlopen and a ctypes call through the ABI.

7. Where the time goes today

From the project’s own study (docs/results/index.md), Scaly beats the best completed CasADi encoding on npmpc, unbumpercars and chain M=9, and loses on race-car (1.09–1.23× slower than SX) and chain M≤5 (2.46× slower than SX at M=5). The 22 September hand-optimization study (internal/notes/perf_2026_09_22) decomposes the race-car N=200 Hessian: the derivative assembly outside the mapped loop is 35 % (M4) to 45 % (Zen 4, gcc) of the kernel; fusing it lets 6 of 16 stage-block entries die; after that, per-lane libm trig dominates on x86.

I reproduced the shape of that on a different machine to anchor the proposals. Race-car constraint-Lagrangian Hessian, lower triangle, N = 40 (246 variables, 400 non-zeros), generated by the current tree, timed with a minimal harness (best of 7 × 20 000 calls; cloud Xeon at 2.1 GHz, 2 vCPU, not the reference machine, so read ratios rather than absolutes):

8.1 Fusion across the mapped call C-77 / C-8 step 0–1

I agree with the ordering in the 22 September note: this is the first step on both machines, and nothing else in the list compounds as well with it. Two implementation remarks from reading the code:

  • The cheapest first cut does not need the full range machinery: after scalarize, a callee with scalarized=True reached only through a FOR{CALL} can be spliced into the loop body with its parameter views rewritten as base + start + stride·it (the VMAP rule already builds exactly those offsets). Then extend fuse_elementwise from “single-store producer loop” to “producer loop whose store index is an injective affine function of its loop variables”; the transpose and gather in Figure 2 are then consumers with index maps that compose into the producer’s store. The final gather → res is a permutation, so it inverts into a store in the producer rather than a load in the consumer (“sink the scatter”).
  • The combine_scatter_sums accumulation (zero-fill + two scatter-adds with overlapping stage windows) is the one place where a stage writes into its neighbour’s rows. For a multiple-shooting Hessian the overlap is the shared state block; peeling it as res[block_k] = H_k^{own} + H_{k−1}^{next} keeps the loop parallel (and lane-able), whereas a naïve fused scatter-add would introduce a loop-carried dependence.

8.2 JIT toolchain N1

The JIT invokes cc, which is gcc on most Linux systems. On this Xeon clang 18 is 17 % faster than gcc 13 on the generated race-car Hessian at identical flags; the project’s own Zen 4 measurement (C-81, point 7) found 40 %. The cause is gcc’s refusal to vectorize a loop containing a call without a SIMD clone and a weaker SLP on long scalar trees. Proposal: probe for clang (then zig cc, then cc) at first use, record the choice in the cache key (already done for flags), and allow SCALY_CC to override. Also align the default -O2 with the -O3 the benchmark harness passes through SCALY_CC_OPT (worth 5 % on gcc here, nothing on clang), so that users see the published numbers.

8.3 One oracle per iterate, cached on new_x N2

solvers/nlp.py builds base (f, g), grad (∇f), jac (sparse ∂g/∂x) and hess (sparse ∇²L) as four separate Functions, and the IPOPT wrapper (scaly_ipopt/codegen.py) ignores the new_x flag in every callback. At each iterate the primal of every stage is therefore evaluated up to four times, and the forward tangents of the Jacobian again inside the Hessian’s forward-over-reverse sweep. Because nodes are interned, simply building one multi-output Function {f, g, ∇f, J} makes lowering share every common subexpression automatically, including inside the scalarized stage bodies. The wrapper evaluates it when new_x is true and serves eval_f/eval_g/eval_grad_f/eval_jac_g from the cache; SQP, which always needs all four, calls it directly. The Hessian stays separate (it depends on λ and is not requested at every trial point). This is the one closed-loop line where Scaly currently loses (race-car IPOPT, function evaluation 0.484 ms against 0.376 ms for CasADi) and it is orthogonal to all the kernel work. Keep the separate oracles for the C API and CasADi compatibility layer.

8.4 Explicit lanes C-79

The design in the todo (tinygrad’s shift_to on the mapped axis, W from preprocessor target macros, one always_inline body plus a clamped remainder call, gnu and c render modes) is sound and I have nothing to add to its structure. Two remarks. The measured result that per-lane libm leaves the widened kernel at 2.1× the hand-written one on Zen 4 means the payoff on x86 is capped by the decision not to use a vector libm; keeping that decision, it may be worth letting C-79 emit the __attribute__((simd("notinbranch"))) declaration block behind an opt-in macro (SCALY_VECTOR_LIBM), since the note shows it reaches the hand kernel on gcc from scalar source without changing the generated arithmetic. Second, lanes need affine-in-lane indices, which is why N5 below matters.

8.5 Input-free procedures and value-aware constants N3

In the Jacobian trace a PROC with input_count = 0 is mapped with no arguments (starts=[]) and called four times to write the same four constants; its output is then multiplied by 0/1 mask tables. Two small passes remove this class of code:

  1. Interprocedural constant propagation: a scalarized PROC with no inputs whose stores are all literals is replaced at every call site by a constant buffer (tiled for a VMAP), after which fold_arith already turns the loads into literals.
  2. Value-aware CONST lowering, a generalization of C-78’s tile folding: a constant whose entries are all equal is a scalar; one with period P is k[i mod P]; a 0/1 mask multiplying a value in an elementwise op is lowered as a loop over the mask’s support (a gather) rather than a dense multiply. This is also the likely identity of the three N-growing double tables in C-57 (k0 is 4 800 ones at N = 50).

8.6 Keep loop nests; unroll tiny loops N5

Elementwise, stack, concat and broadcast rules iterate over a flat index and recover coordinates with / and % (_coord_p, _broadcast_index_p), which is why the trace contains s1[((v0*2)+v1)] = s0[((v0*4)+v1)] with v0 = j/2, v1 = j%2. Emit a nest of ranges from the shape instead (one range per non-trivial axis, as _lower_transpose already does), so every index is affine in the loop variables. That removes the integer divisions, makes fuse_elementwise’s index substitution simpler, and is what C-79 and C-8 need, because j mod 2 is not affine in a lane variable. Independently, loop-form PROCs (the entry point is never scalarized under auto) should fully unroll loops with a static trip count ≤ 8 before the second fold_arith; the four-trip copies of zeros in the trace then disappear.

8.7 Reciprocals, tiles, peeling C-78

Confirmed on x86: replacing all 14 invariant divisions in the race-car stage body by multiplications with the reciprocal that hoist_invariant already computes gives 6 % on clang and 1.5 % on gcc. The rewrite should happen at expression level before AD so primal and adjoint share one reciprocal node (today the prologue computes 1/params[2] and the body still divides by params[2]). It changes the last bit, so the policy-flag caveat in the todo stands.

8.8 Chain: exploit symmetry, not colouring C-11 refined

I checked whether a better vertex ordering for the star colouring could reduce the number of forward-over-reverse sweeps. It cannot: on the chain Lagrangian (N = 10) the greedy colouring in column order, largest-first and smallest-last orderings all give 12 colours at M = 3 and 24 at M = 5, equal to the maximum degree + 1, i.e. the size of the dense per-stage Hessian block, which is a lower bound for any colouring. Race-car gives 4 = 4. The colouring is therefore optimal, and the 2.46× gap to SX at M = 5 is the price of computing each dense b × b stage block as b Hessian-vector products. The remaining lever is symmetry: a second-order reverse sweep over the scalarized stage SSA (edge pushing, or its live-variable variant) computes only the n(n+1)/2 lower-triangle entries and exploits the sparsity of nonlinear interactions inside the stage, which is effectively what SX’s symbolic Hessian does. Because the stage body is already scalar SSA after C-44, this can be a program-dialect transform on a single callee, with the VMAP structure untouched; the chain’s partially separable Lagrangian (a sum of stage terms) means the per-stage results simply scatter-add into the global pattern.

8.9 Small, cheap items N4, N6

  • Structural PROC deduplication (N4). Callees are deduplicated by name only (callee.name not in ctx.callees). The residue-class bake of C-45 produces different names for bodies that lower to identical code (both defect_fwd…_defect_z in the trace). Since program nodes are interned, two PROCs are equal iff their parameter lists and body tuples are identical up to the PROC name; hash that tuple after scalarize, merge, and rewrite call sites. Mainly code size and compile time, which matter for the compile-cap cells.
  • restrict on internal callees (N6). The lowering knows that a callee’s output buffers are private scratch or disjoint output views, and inputs are const. Emitting double* restrict for outputs (and __builtin_assume_aligned(p, 8) is already implied) lets the compiler keep loaded values in registers across stores in loop-form callees such as the scatter-add loops; the ABI entry must stay unqualified. Emit it only where the pass pipeline has proved disjointness (the same facts coalesce_stores uses).

8.10 Parameter-only prologue C-80

Natural companion to N2: once the NLP oracle is one Function, the part of it that depends only on p can be split off with the same machinery hoist_invariant uses, and the solver wrapper runs it once per solve.

9. Things measured that do not help negative results

  • Colouring order (natural, largest-first, smallest-last): identical colour counts, all at the clique lower bound (Section 8.8).
  • Removing noinline from the forward helpers: no change (20.2→20.5 µs gcc, 16.8→16.9 µs clang), consistent with the M4 and Zen 4 notes; inlining pays only once consumers are fused.
  • sincos: both gcc and clang already merge each sin/cos pair into one sincos call under -fno-math-errno; nothing to do in the renderer.
  • Extra gcc flags: -fno-stack-protector (Ubuntu enables the protector by default) changes nothing; adding -ffp-contract=fast -fno-semantic-interposition was 9 % slower.
