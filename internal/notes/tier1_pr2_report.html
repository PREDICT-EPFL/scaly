New capability

x.max(), x.min(), sc.reduce_max(x), sc.norm_inf(x), sc.norm_1(x)   # NaN-propagating scalar reductions

with sc.options(nonsmooth="first"):          # "split" (default) | "first" | "error"
    g = sc.gradient(cost, x)                   # tie convention baked into this graph
sc.set_options(nonsmooth="split")              # process default
  • Differentiable extrema: maximum, minimum, max and min are now differentiable in forward and reverse mode, with sparsity. At a tie:
    • "split" shares the derivative equally among the tied arguments, as JAX does.
    • "first" gives it all to the left operand, or to the lowest index.
    • "error" keeps the old refusal.
    Where one operand is NaN, the derivative follows the value C's fmax returns.
  • abs: the derivative is now sign(x) with abs'(0) = 0. It used to be NaN at 0.
  • Options system (new): sc.options is a context manager backed by a ContextVar, so it is thread- and task-local. sc.set_options changes the process default, sc.get_options reads the current setting, and sc.Options holds the settings.
    • An unknown name or value raises at the call.
    • Options are read when a derivative graph is built. A graph built under a setting keeps that setting after the block ends, and the choice reaches the C source and the JIT cache key automatically.
  • A Python number passed to maximum or minimum now takes the other operand's dtype, the same rule PR 1 introduced for comparisons.

  • max costs no more than the existing sum. Both are serial: 0.5–0.8 ns per element against NumPy's 0.08.
  • Finding (pre-existing, shared with sum): the reduction rule keeps the accumulator in the output array (res[0][0]). The C compiler cannot keep it in a register because that array may alias the inputs, so every trip loads and stores it. That is most of the 6–7× gap to NumPy. norm_inf also materializes abs(x) first instead of fusing it. Filed as C-89. It needs scalarize to understand local scalar variables, which it does not today, so I kept it out of this PR.
  • Finding: the "first" gradient of max embeds an n-long index constant in the C source. Build time is 131 ms at n = 10⁵ and 1.4 s at n = 10⁶, against 21–25 ms for "split". Runtime is the same. It only matters for very large reductions in "first" mode; lowering constants in an affine range to arithmetic would remove it.
  • Build time for every other variant is 17–27 ms.

Deviations from the plan

  • The plan said derived Functions would record the options they were built under, and that listings would show them. I did not add that. The convention is already visible in the derivative graph itself (a different select structure), so a separate record would only duplicate it.
  • sc.set_options was added next to the context manager, for notebooks and scripts that want one global setting.
  • maximum and minimum now adopt the dtype of a Python-number operand.
