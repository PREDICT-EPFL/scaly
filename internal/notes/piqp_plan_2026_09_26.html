PIQP in Scaly: status and plan

Tier 1 delivered, the revised plan for Tiers 2–4, and what three review agents found · 26 Sep 2026 · supersedes the tier ordering in piqp_in_scaly_2026_09_25.html · living copy in the claude.ai project as claude/piqp-plan.md

In one paragraph. Tier 1 is finished on claude/tier1-primitives: 9 PRs, 1 057 tests. It gives Scaly the primitives a solver needs: comparisons and selects, reductions, accumulating scatters, scan, while_loop, in-place carries and custom derivatives. It also makes derivatives through loops fast: a single-shooting MPC Hessian runs in a fixed number of loops, 3.5× faster than before the work, and an RK4 Hessian 15× faster.

Three agents then challenged the Tier 2+ plan, running experiments on the vendored PIQP sources and on MPC and Maros–Mészáros KKT patterns. Four things came out of that:

  1. The dense slice. PIQP's dense mode is a condensed Cholesky, not an LDLᵀ. A masked dense LDLᵀ written in a scan runs 10–50× slower than LAPACK.
  2. MPC needs no runtime indexing. MPC KKTs in stage order factor into an exactly periodic pattern, so a scan over stages with dense block kernels covers them using Tier 1 machinery only. It is the most accurate form measured, and it attacks the QP time that is 84–91% of closed-loop SQP time on the repo's benchmarks.
  3. The generic sparse LDLᵀ is expensive. It needs runtime integer indexing, a per-scan in-place proof, left-looking rather than up-looking columns, and two further compiler features before it can come within 2× of QDLDL.
  4. About ten algorithmic details were missing or wrong in items #19–#31.

The revised plan therefore builds a NumPy reference PIQP first, then dense block kernels, then a dense-condensed PIQP, then the stage-periodic sparse solver for MPC and SQP. The generic sparse path is gated behind measurements, with explicit kill criteria.

Limits that shape Tier 2:

  • Index tables are fixed per operation: every scan step touches the same entries, and there is no runtime integer indexing.
  • Loop bodies are either unrolled (compiles slowly past about 4k operations) or lowered as one loop per operation (memory traffic on every term).
  • A Python call costs about 4.7 µs.
  • Open Tier 1 items are C-89, C-90, C-92, C-94–C-100 (see internal/todo.md).

2. What the review of the Tier 2+ plan found

Three agents reviewed the draft independently, covering numerics, compiler feasibility and strategy/testing. All experiments ran in the Linux VM; the scripts are under $HOME/review-agents/plan/ in the VM.

2.1 Numerics

  • Dense mode. PIQP forms the condensed n×n matrix C = P + reg + AᵀA/δ + GᵀW⁻¹G and factors it with Eigen's LLT (dense/kkt.hpp:73-84,140-160). The multistage mode uses the same algebra blockwise (sparse/multistage_kkt.hpp:424-431). The planned no-pivot LDLᵀ could never reproduce PIQP's dense iterates.
  • Sparse default. PIQP uses the full KKT (n+p+m) ordered by Eigen's AMD and factored by Davis's up-looking LDL, with fused multiply-add suppressed. The only failure test is an exact zero pivot.
  • Fill and ordering on MPC (N = 100, nx = 12, nu = 4, 6 inequality rows per stage). The condensed form in stage order has 0.6× the work of full KKT + AMD, in 100 supernodes of about 16 columns:
    Form and orderingDimensionnnz(L)Multiply-adds per factorizationSupernodes (mean size)Padding, one column scan
    Full KKT + AMD (PIQP default)3 43056 355531k1 528 (2.2)1.76×
    Condensed, stage order1 61231 266337k100 (16.1)1.09×
    Level scheduling gains nothing on MPC, because the elimination tree is almost a path (height about 0.97 n).
  • Numerical accuracy without pivoting, at late-iteration regularisation. Ordering sets the forward error; backward error stays at about 1e-17 in every case, and no wrong-sign pivots appeared. At δ = 1e-10 the x-error is 5e2 in natural primal-first order, 1e-4 for full KKT + AMD, and 2e-14 for the condensed (duals-first) form.
  • Iterate agreement. PIQP's own dense and sparse runs differ by 1e-13 to 1e-8 relative per iterate. "Iterate-by-iterate" therefore means agreement within tolerance plus an identical trace of discrete decisions, not bitwise equality.
  • Maros–Mészáros. On these problems a single padded column scan wastes up to 47×, so contiguous segments chosen by dynamic programming are essential there. Up-looking LDL needs nested ragged padding of 3–50× and is rejected for Scaly; left-looking fits.

  • Where the 3.3× LDL gap comes from: about 1.5× from the left-looking formulation, 1.43× from padding, and 1.5× from missing index-aware fusion. Closing it needs ragged inner loops and a minimal C-54.
  • Missing capabilities:
    • a scan step index as a body input;
    • a sparsity override on custom_derivative;
    • a guard on trajectory memory;
    • carries of several tensors or mixed dtypes;
    • workspace spill for int64 buffers;
    • native solver statistics for a backend="scaly" that is a plain Function, not a SOLVER_CALL.

2.3 Strategy, testing and benchmarks

  • Where the value is (docs/results/index.md, closed-loop SQP with vendored PIQP): the QP is 84% of the time on chain, 91% on race_cars, 52% on npmpc and 11% on unbumpercars. These QPs are sparse and stage-structured, with 0.3k–2.3k KKT rows. The dense slice does not touch them; the stage-periodic path does.
  • Periodic structure. With stage-interleaved ordering [uk, λk, xk+1], the pattern of L is identical for every stage except the last, for (nx, nu) = (6, 2), (12, 4) and (27, 3). One stage costs about 0.8k, 6k and 66k flops.
  • What a native PIQP buys:
    • pure-Python distribution;
    • no LGPL code in the shipped solver;
    • static memory for embedded targets;
    • fusion with the QP-data oracle (today Ruiz is recomputed on every update);
    • settings folded at generation time, and sensitivities.
  • Test data already on disk: 138 Maros–Mészáros problems (73 small), 29 infeasible LPs, and SQP/MPC .mat sets, all in the vendored PIQP test directory (Apache-2.0). Golden traces can come from the vendored headers, which an agent compiled into a Linux harness, and from max_iter = k reruns.
  • Licensing: do not port PIQP's sparse/ldlt, which is modified LGPL code. Write it fresh from QDLDL (Apache-2.0) or the textbook algorithm. Eigen's Amd.h is MPL2 if an exact AMD is ever needed.

3. The revised plan

4. Corrections to the algorithm items (#19–#31)

From the vendored PIQP 0.6.2 sources (third_party/piqp/include/piqp/).

  1. Dense mode is the condensed Cholesky described in §2.1. The multistage factorization always reports success, so its retry path never fires.
  2. KKT forms. The sparse default is the full KKT, and there are 4 elimination modes plus multistage (settings.hpp:18-26), not the two forms the plan listed.
  3. Box bounds never add KKT rows. They fold into the x diagonal, with their own Ruiz vector and bound scaling. The boundary shift adds ε to all box duals if any one of them is below ε.
  4. Two-sided inequalities hl ≤ Gx ≤ hu keep two (s, z) pairs per row but contribute one KKT row, with W = [Σ 1/(s/z + δ)]⁻¹.
    • "Infinite" means |value| ≥ 1e30.
    • A row infinite on both sides is kept, with G zeroed and bounds set to ±1, and it still counts in μ. Dropping it at generation time changes the iterates.
  5. Proximal centres (ξ, λ, ν) move only when a residual falls by at least 5%. The ρ and δ update rules have iter < 5 and prox-infeasibility special cases, and a separate branch when there are no inequalities.
  6. Initial point. Factor with ρ = 1e-6 and δ = 1e-4, solve once, shift by max(0, −min), and set μ = max(μ, 1e-10). Then project each pair onto the central path with z = (c + √(c² + 4μ))/2, s = z − c. There is no margin.
  7. Iteration order (solver.hpp:579-878):
    1. terminate on the previous residuals, with OR semantics on absolute and relative tolerance and the duality gap included;
    2. infeasibility tests;
    3. boundary shift;
    4. fine-tune switch;
    5. factor, inside the retry loop;
    6. predictor;
    7. σ = clip(·)³;
    8. corrector;
    9. separate primal and dual steps;
    10. μ update;
    11. ρ, δ and centre updates.
    Each iteration costs one factorization and two solves.
  8. Retry and refinement. The first failure only switches refinement on, permanently. Later failures multiply ρ and δ by 100, up to 10 times. In refinement mode the matrix is perturbed by 1e-8 + ε²·max|diag|. Below δ ≈ 1e-9, refinement effectively just swaps in δ ≈ 1e-8.
  9. Ruiz exits early at max|1 − d| ≤ 1e-3. limit_scaling maps values below 1e-4 to 1 and caps values at 1e4. Cost scaling is off by default. Implement it as a while_loop, or as a scan that freezes after convergence.
  10. Warm start does not exist in 0.6.2. restore_dual sets s = 1e30 where z = 0.
  11. Fraction to boundary is τ·min(1, min over components with ds < 0 of −s/ds), with no ε guard.
  12. 1/z = ∞ on infinite-bound rows. PIQP computes it and never reads it. In Scaly, masking by multiplication would produce NaN, so masks must use where.
  13. A non-finite solve result is ignored by PIQP. Scaly will add an isfinite check that triggers a retry, as a documented deviation, and inject a zero pivot to test the retry path.

5. Benchmarks, gates and kill criteria

  • Metrics:
    • native solver time from SolverStats, and Google Benchmark on the kernels (both without Python);
    • iterations, time per iteration, status and residuals;
    • build, render and compile time; C lines and .text size; workspace bytes; generation RSS.
  • Baselines:
    • vendored PIQP in dense, sparse and multistage modes, rebuilt with native flags for the head-to-head;
    • PIQP's LDLt through a C++ driver, as a QDLDL stand-in;
    • LAPACK for the dense kernels;
    • OSQP, Clarabel and HPIPM as optional extras on the Mac.
  • Problem families:
    • random dense QPs, n ∈ {5, 10, 20, 50, 100};
    • the small Maros–Mészáros subset;
    • linear MPC with nx ∈ {4, 12, 27} and N ∈ {10, 20, 40, 100};
    • the SQP QP corpora from chain, race_cars, npmpc and unbumpercars;
    • closed-loop episodes where only the QP backend is swapped.
  • Kill criteria:
    • Dense kernels: more than 2× slower than LAPACK at n = 32–64 → limit dense to unrolled code at n ≤ 16.
    • Reference: identical decision traces on fewer than 90% of problems → stop and diagnose before any sparse work.
    • Periodic path: more than 3× slower than PIQP's LDLt, or 2× slower than multistage, after one optimization round → rethink block lowering, or call BLASFEO through an external-procedure ABI.
    • Generation time: growing faster than 2.2× per doubling of nnz(L), or over 10 s at 50k → stop.
    • Runtime indexing: if it cannot land in one medium PR with AD, in-place and unchanged snapshots → drop the generic sparse path.
    • Value: if vendored multistage alone halves closed-loop QP time and Scaly cannot beat it → re-scope to distribution, embedded targets and differentiability.
    • Default: never make Scaly the default while there are status regressions.

6. Decisions for Colin

  1. Re-scope: the stage-periodic MPC/SQP path first, with the generic sparse LDLᵀ gated behind M5. Recommended.
  2. Dense slice: condensed Cholesky on new dense block kernels, matching PIQP's dense mode, rather than an LDLᵀ. Recommended.
  3. NumPy reference PIQP as the oracle between vendored PIQP and Scaly, plus checking a curated Maros–Mészáros subset (Apache-2.0) into tests/data. Recommended.
  4. Ordering: stage ordering and SciPy's SuperLU MMD now; port an AMD (Eigen's Amd.h, MPL2) only if M5 needs it.
  5. Parity semantics: identical decision traces plus a tolerance on iterates, not bitwise; -ffp-contract=off only for parity tests.
  6. Work only possible on your Mac: the baseline timings of vendored PIQP and the SQP QP corpus dump need the native plugin. I can prepare the scripts, or you can run them.
  7. Still open from Tier 1: merge segment_sum, segment_max and segment_min into one segment operation with a combine function.
