Tier 2 · PR 1 report

T2-1 · the step number as a loop-body input (C-101) · branch claude/tier2-sparse · 26 Sep 2026

Summary. A scan or while_loop body can now take the step number as an int64 scalar (index=True). The generated C computes it from the loop counter, so no table of step numbers is stored. This holds forwards, in forward-mode tangent loops and in the backward scan of reverse mode, where the number counts down.

This is the first building block Tier 2 needs: the column loop of a sparse factorization has to know which column it is on to read its pattern tables.

Changes that serve any loop

  • A float table read one entry per step whose entries are all equal is now passed as the value. The table of ones in a summed output's cotangent is gone from every such gradient.
  • Procedures holding int64 values now expand to scalars. Before this, a body using the index ran 1.7× slower than the table it replaces.
  • sc.where refuses a Python bool. That is what k == 0 produces on an expression, and it silently selected one branch for good.

Suite: 1 086 passed and 88 skipped, plus the four tests that fail only in this VM (the Google Benchmark link and CasADi's libstdc++), unchanged. ruff and ty are clean. Mutation checks: 10 of 10 mutants were killed.

1. What the capability is

@sc.function(sc.G(sc.L("z", 2), sc.L("k", sc.TensorType((), sc.dtypes.int64)), sc.L("u", 1)), sc.L("znext", ...))
def tv_step(inputs):
    z, k, u = inputs
    t = 0.1 * k.cast("float64")
    return sc.stack([z[0] + 0.1 * z[1], z[1] + 0.1 * (u[0] - t * z[0])])

(z_final,) = sc.scan(tv_step, z0, [(us, 0, 1)], length=50, index=True)
carry, n = sc.while_loop(go, damped_newton, x0, max_iter=40, index=True)   # body(carry, k)

The index has no derivative. Sparsity, forward mode (one seed or many), reverse mode, Hessians and in-place carries all work with an indexed body.

2. How it was done

PieceChange
function/sugar.py
  • scan(index=True) prepends (step_numbers(length), 0, 1) to the sliced inputs. step_numbers is an int64 constant 0…N−1, hash-consed.
  • Consequence: every existing scan rule applies unchanged. Reverse mode walks the table with a negative stride, and multi-seed forward mode passes it through as a non-differentiable slice.
  • while_loop(index=True) takes a body (carry, k). Validation is in _check_index_input and the WHILE spec rule.
passes/lowering.py
  • _constant_per_step handles a constant table read one entry per step. If the table is an integer table, the entry becomes ctx.index_at of the entries along the walk: arithmetic where it is affine, with only a non-affine residual kept as a table. If it is a float table whose entries along the walk are equal, the entry becomes the value.
  • The entry is stored into a one-element local each step and passed by pointer (_scalar_arg). A while body receives the loop counter itself.
  • The unused table is dropped by the existing dead-buffer pruning.
ad/forward.py, ad/reverse.py
  • The while tangent bodies keep the index input.
  • The masked backward step of a while loop substitutes the index with its own step input, cast to int64.
ad/sparsity.pyOnly a slice that brings in dependence counts as "moving". The index brings none, so a long indexed loop still stops its pattern walk at the first repeat: 200 000 steps take milliseconds rather than about 15 s.
passes/program/scalarize.py, lowering.py
  • int64 joins _SCALARIZABLE.
  • Scalar expansion now keeps a store's conversion as an explicit cast wherever the stored value's type differs from the buffer's. This is the hazard that kept non-float procedures out.
  • float32 and int32 stay excluded.
ir/expr.pywhere raises TypeError on a Python bool condition, pointing to sc.equal.
Docsdocs/guide/functions.md has an index example for scan and while_loop, and the == caveat. The example was run.

3. Tests

New file tests/integration/test_loop_index.py has 27 tests, and tests/passes/test_scalarize.py gains 3. Every derivative check runs with SCALY_STRICT_JVP_MANY=1.

  • Scan values and derivatives. The value matches NumPy. Jacobian, gradient and Hessian with respect to the initial state and the controls equal the explicit-table version to 1e−12 and match finite differences.
  • Generated C. No integer table appears in the C for the value, gradient or Hessian. The backward scan passes (N−1 − k).
  • Walk direction, lengths and tables.
    • A slice walked backwards leaves the step number unchanged.
    • A zero-length scan works.
    • A non-affine integer table (3 1 4 1 5 9 2) is still read per step, and its gradient is correct.
    • A varying float table stays a table.
  • Sparsity. The pattern equals the table version's, and a 200 000-step indexed loop finishes within the time bound.
  • while_loop.
    • A damped Newton iteration whose damping depends on k matches NumPy from three starts, in value and step count.
    • Jacobian, gradient and Hessian match finite differences, and forward and reverse mode agree to 1e−12.
    • The body receives the counter by pointer.
  • Scalar expansion.
    • A hand-built procedure storing a float into an int64 slot keeps the cast.
    • int64 procedures scalarize.
    • A float→int cast inside one truncates toward zero, like C.
  • Validation and the == trap. An index of the wrong type, shape or position is rejected, and where(k == 0, …) raises.

Changed expectation. Two assertions that int64 procedures are never scalarized now state the opposite (test_lowering, test_scalarize). The float32 and int32 cases still assert the old behavior.

Mutation checks (10 of 10 killed):

  • no table elision
  • no uniform-value elision
  • a constant instead of the counter
  • a reversed table
  • the counter plus one in while
  • no index substitution in the backward while step
  • index input dropped from the while tangent body
  • the old "moving" rule
  • no store cast in scalar expansion
  • int64 removed from _SCALARIZABLE

  • With int64 scalarization, the index costs the same as a stored table and stores nothing: at N = 400 that is 3.2 kB of static const gone.
  • The time-in-carry workaround is 25–35% slower for Hessians, because every tangent carries the extra entry.
  • The gradient no longer holds the N-entry table of ones.

5. Open points

  • float32 and int32 procedures still do not scalarize. A float32 value computed in double by C's promotion rules is the remaining hazard. This is not needed for Tier 2.
  • A while loop's backward pass still runs all max_iter steps (C-92). Its step input remains a float64 table, cast to int64 for an indexed body.
  • Expr == Expr is still identity: expressions are dict keys throughout the compiler. Only where catches the mistake.
