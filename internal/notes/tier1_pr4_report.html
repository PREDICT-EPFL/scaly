New capability

z_final, costs = sc.scan(step, z0, [(us, 0, 1)], length=N)   # step: (carry, *slices) -> (carry', *ys)
  • One loop, whatever N: the scan becomes a single SERIAL loop that calls the body procedure. The generated C is the same size for N = 10 and N = 100 000.
  • Slicing: inputs are sliced the way vmap slices them, with a zero stride for broadcasting. Negative strides also work, so a scan can walk a sequence backwards.
  • Outputs and carries: stacked outputs are written in place, directly into the Function's output buffer when they are one. The carry can have any shape, including a matrix.
  • Carry storage: the carry alternates between two slots selected by k % 2. No step copies it, and no call reads and writes the same memory. When reverse mode needs the per-step carries, the same buffer grows to N+1 slots and holds the trajectory. There is no extra copy in either case.
  • Derivatives are scans too:
    • Forward mode runs one scan whose carry is [c, ċ].
    • Reverse mode runs one scan over the reversed steps, reading the stored carries backwards. The slices' cotangents accumulate into their outer tensors through PR 3's accumulating scatter.
    • Sparse Jacobians and symmetric Hessians work through a scan.
  • Exact structural sparsity: the body's dependence pattern is stepped through the loop. When no input changes from step to step, the patterns are eventually periodic; the walk stops at the first repeat and reads the answer off the cycle, so N = 100 000 takes milliseconds.

Findings and deviations

  • When both the final carry and a stacked output of a scan are differentiated, reverse mode builds one backward scan per output. This is correct by linearity but does the work twice. Filed as C-91: one backward scan seeded with every cotangent.
  • A final carry that is also a Function output is copied out of the carry buffer once, which costs O(carry). Stacked outputs are written in place.
  • The multi-seed forward rule (jvp_many) has no structural rule for scan, so dense Jacobians use the existing per-seed fallback: one tangent scan per seed. It is correct, and reverse mode or sparse Jacobians are the efficient route.
  • Program passes needed no changes. hoist_invariant already treats a loop-dependent view as varying, and scalarize interprets the loop in order.
