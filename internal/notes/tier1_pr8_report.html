What was wrong

sc.hessian is jacobian(gradient). The Jacobian pushes the N identity seeds through batched forward mode (jvp_many), but jvp_many had no rule for SCAN or WHILE. It therefore fell back silently to one pass per seed. The Hessian of the single-shooting MPC cost became N near-identical blocks, each with its own forward tangent scan, two adjoint scans and several accumulation loops. At N = 10 that was 127 loops, and at N = 200 it was 2 407.

New capability

A loop's tangents for n seeds are now computed by one loop, whose carry is [c, Dc]. Dc holds the (n, *c.shape) tangents, seed-major. The body's own tangent is itself a multi-seed pass, so work that does not depend on the seed, such as sin/cos of the state, is computed once per step instead of n times. This is the Hessian of the MPC cost at N = 10 in full, and it is the same set of loops for any N:

for (k = 0; k < N; ++k) m8_step_raw(...);                        // primal rollout, carries stored
m8_shoot_raw(...);                                                // the call's own outputs (see C-95)
for (k = 0; k < N; ++k) m8_step_scanfwdN_0_raw(...);            // one tangent scan: carry [x, Ẋ ∈ ℝ^{2×N}]
for (k = 0; k < N; ++k) m8_step_scanadj1_..._scanfwdN_raw(...); // adjoint scan for the stacked states
for (k = 0; k < N; ++k) m8_step_scanadj2_..._scanfwdN_raw(...); // adjoint scan for the stage costs (see C-91)
... 11 short elementwise loops: zeroing, scaling, scatter-add, the transposed store (see C-96)

The rules, all in ad/forward.py:

  • SCAN.
    • Each active sliced input gets its per-step (n, size) tangent block.
    • The final carry, the stacked outputs and the stored carries (output=-1, which forward-over-reverse needs) are read back seed-major.
    • A broadcast input (stride 0) stays one block.
    • A backwards input (negative stride) becomes a block per step.
  • WHILE. The same carry layout. The condition reads only c, so the tangent loop takes exactly the primal's steps. The step count has zero derivative.
  • Reading in place. When a loop input is a strided view of another loop's stored carries, the loop reads that storage directly. _strided_view composes the gathers and reshapes and detects one contiguous block per step. This is what the adjoint scans of a Hessian do with the tangent trajectory, so it is not copied.
  • Calls around a loop. A CALL whose callee holds a loop is differentiated in place. Reverse mode already inlines such a body, so the tangent scan built here is the same hash-consed node as the one built for the gradient's stored carries, and it is computed once. Before this change, it was computed again inside a shoot_fwd helper.
  • Helpers. Multi-seed helpers for VMAP callees that hold a loop use the joint multi-seed pass instead of one tangent per seed.

Also fixed (found while benchmarking): the JIT built each call's workspace as a ctypes array and passed it through ctypes.cast. The cast puts the array in a reference cycle, so every workspace stayed alive until the next garbage collection. A loop of calls of the old N = 200 Hessian grew by about 1.6 MB per call until the VM killed it. The workspace is now a NumPy buffer, zero-filled as before.

  • The loop count is now fixed for the linear body. It still grows for RK4, because above the scalarize budget the multi-seed body's operations over the seed axis become short loops inside the step procedure. The number of loops at the top level is fixed.
  • The run time remains O(N²·step), as it must for a dense Hessian. For RK4 the saving comes from computing the seed-independent work (sin, cos, the primal step) once per step, so the speed-up is modest.
  • Finding: for RK4 at N ≤ 40, the first call is up to 2× slower. The multi-seed step bodies are scalarized into long straight-line procedures, and gcc takes longer on them: at N = 10, compiling takes 906 ms against 377 ms. The run time is better. This is the same scalarize-budget question noted in PR 7.

Deviations and notes

  • Three changes beyond the planned rule were needed for the Hessian you showed to collapse to a fixed set of loops: inlining calls around loops, in-place reads, and the joint multi-seed pass in VMAP helpers. Before calls around loops were inlined, the code shrank but a second forward tangent scan remained inside the call's helper, and the MPC case at N = 40 was slower than before (58.8 against 40.4 µs).
  • Remaining waste, now filed:
    • C-91: two adjoint scans, one per scan output.
    • C-94: the gradient half of each adjoint carry is computed and thrown away.
    • C-95: m8_shoot_raw repeats the primal rollout, because the gradient keeps the call for its outputs.
    • C-96: 11 short elementwise loops are not fused.
    Calling scan directly in the cost, rather than through a shoot Function, avoids C-95 today: at N = 100 that variant takes 75 µs against 115 µs.
  • For this linear-quadratic problem the Hessian is a constant, but constant folding stops at scan, so it is still computed at run time.
