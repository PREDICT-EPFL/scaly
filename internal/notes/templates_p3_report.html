Function templates P3: bare mode and inferred outputs

2026-09-27 · branch claude/function-templates · plan v2, step P3

Summary. @sc.function on its own is enough: def product(A, B): return A @ B called with (4, 4) and (4, 2) arrays builds product__4x4_4x2, and with (3, 3)/(3, 1) builds product__3x3_3x1. output= is optional everywhere: the output tree is read off the same trace, named after the function. A sparse output named like its function no longer breaks the C++ header.

What changed

  • Decorator forms.
    • @sc.function, @sc.function(), @sc.function(name=...) and @sc.function(output=...) on a body with parameters make a bare template.
    • On a body with no parameters they make a concrete zero-input function.
    • Declared slots without output= infer the output.
    • The old two-positional spelling still gets the migration hint.
  • Bare binding (tree.inferred_tree).
    • A tuple argument is structure; its leaves are named p_0, p_1, ...
    • An Expr is a leaf of its shape and dtype, so an int64 index reaches a bare helper (pick__5_sint64).
    • A SymbolicValue declares itself through leaf_tree: a SparseMatrix is S(name, pattern), and its instance token is p plus a digest of the pattern.
    • An array-like is a float64 leaf of its shape; a float, an int, a NumPy scalar and a 0-d array share one instance.
    • Refused, each with the fix: a tuple of numbers ("pass a list or an array for a vector"), a list holding expressions ("build one with sc.stack"), a SciPy sparse matrix ("declare its pattern").
    • The nesting is part of the key and, when any argument is a tuple, of the name (t plus six hex digits). Two calls with the same flat shapes nested differently are two instances.
  • Inferred outputs in one trace. ConcreteFunction(outputs=None) builds the output tree from the traced value. A leaf is named after the template, never after the instance, so of= is the same for every instance. Tuple leaves are f_0, f_1, nested f_0_1: the input rule applied to outputs. A body returning anything else is refused.
  • C++ header. A sparse output's namespace is named by its buffer identifier, which already avoids the function's own symbol. A sparse output named like its function used to redeclare the function inside its own namespace.
  • Typing.
    • @sc.function: Function[P, ..., R, Any], the body's own signature on the symbolic side.
    • @sc.function(): a _Bare protocol.
    • output= alone: an overloaded _OutputOnly protocol, Function[[], [], SO, NO] for a zero-parameter body.
    • Declared slots without output=: an _Inferred protocol per width, the body's return type as the symbolic output and Any as the numerical one.
  • The argument-keyed fast path now keys on the nesting too, and skips lists, which may hold expressions.

Tests and mutation checks

tests/function/test_bare.py (8 tests) covers:

  • many shapes, one trace each, and a symbolic call reusing a numerical call's instance;
  • numbers and lists as leaves, and the three refusals;
  • tuples as structure, and nesting in the key and name;
  • Expr dtypes, and sparse patterns;
  • inferred outputs (declared inputs, zero parameters, output= alone, a list returned);
  • output names following the template, arity errors, and the repr.

test_name_clash.py compiles the C and C++ headers of a dense and a sparse output named like its function. The typing tests cover the four new decorator forms.
