Tier 2 · PR 4 report

T2-4 · SparseMatrix (C-104) · branch claude/tier2-sparse · 26 Sep 2026

Summary. sc.SparseMatrix is a matrix whose pattern is fixed when the graph is built, stored as CSC in NumPy. Its values are an Expr in CSC order.

How it is built. Every operation works out the result's pattern at generation time. It expresses the values with ordinary static-index ops (gather, products, segment_sum, scatter). So derivatives, sparsity analysis and code generation see nothing new: the class is a library value in the new package scaly.linalg, and the IR type does not change.

Across a Function boundary the matrix is its compact values vector, with sparsity as the output metadata.

Performance. A KKT matrix with 42 000 nonzeros is assembled in 37 µs, which is 16× faster than SciPy's bmat in Python. K @ z runs within 2.5× of SciPy's C matvec. AᵀA with a build-time product pattern takes 29 µs, 6.6× faster than SciPy recomputing the pattern every call.

Suite: 1 154 passed, 88 skipped; the same four VM-only failures. ruff, ty and the docs build are clean. Mutation checks: 11 of 11 killed, after two tests were sharpened.

1. The API

GroupMembersNotes
Constructionsymbol(name, pattern), from_pattern(pattern, values), from_coo(rows, cols, values, shape), from_dense(x, pattern=None), from_scipy(a), from_sparse_jacobian(sj), diag, identity, zeros, block(grid)
  • A pattern can be a SparsityType (coordinate order), a boolean mask (row-major) or a SciPy matrix (stored order). Values are reordered to CSC with one gather.
  • from_coo sums duplicates with segment_sum.
  • block takes SparseMatrix, dense rank-2 expressions, SciPy matrices or None.
Arithmetic+ − neg, * scalar, / scalar, A * B (Hadamard product), scale_rows, scale_cols, add_diagonalAdd and subtract use the pattern union, reading zero where an operand has no entry. The Hadamard product uses the intersection.
ProductsA @ x, A @ X, x @ A, X @ A, A @ B
  • Dense operands: one product per stored entry, then a segment sum per row.
  • Sparse × sparse: every pair of an entry (i,k) of A and an entry (k,j) of B is enumerated at build time. The unique output keys form the pattern, and the values are a segment sum of the pair products.
Structure.T, tril, triu, select, with_pattern, diagonal, to_dense, coordinates, position, sparsity, to_scipywith_pattern places the values on a larger pattern: it is how two matrices share one pattern before a loop.

Operator deferral. Expr operators now return NotImplemented for an operand whose class sets __array_ufunc__ = None, which is NumPy's opt-out convention. As a result, x @ A reaches SparseMatrix.__rmatmul__, and NumPy scalars and arrays also defer to the matrix.

2. Tests

tests/linalg/test_sparse_matrix.py has 28 tests.

  • Construction.
    • COO: duplicates summed, unsorted input, and a 3-cycle permutation that is not its own inverse.
    • from_pattern in all three pattern kinds, including a permuted coordinate list.
    • Constants, from_dense with and without a pattern, and a sparse Hessian round-trip.
  • Algebra against SciPy / NumPy. Random 7×5 and 5×6 patterns with symbolic values, 15 matrix-valued operations: add, sub, neg, two scalings, div, Hadamard, row and column scaling, transpose, sparse×sparse, tril(−1), triu(1), add_diagonal, and a block with a dense block. Also the four dense-operand product forms, the diagonal with missing entries, with_pattern and select.
  • KKT. [[P + ρI, Aᵀ], [A, −δI]] equals SciPy's bmat, and its pattern size matches.
  • Derivatives. A nonlinear function through (A C) x and Aᵀ sin(y):
    • the gradient in the values matches finite differences;
    • forward and reverse mode agree in strict multi-seed mode;
    • the Hessian in x matches finite differences of the gradient.
  • Function boundary. A product's compact values cross the Function boundary with output_sparsities, and the reconstruction equals the dense product.
  • Validation. Bad indptr, unsorted or duplicate rows, out-of-range indices, wrong value shapes, duplicate COO in from_pattern, non-scalar scaling, and unsized or mismatched blocks are all rejected.

Mutation checks (11 of 11 killed):

  • union misses read the wrong entry
  • sparse×sparse pairs without offsets
  • transpose without permutation
  • COO permutation inverted
  • matrix product lanes transposed
  • row scaling by sorted indices
  • block column offsets from rows
  • with_pattern containment check removed
  • Expr deferral removed
  • tril sign
  • missing diagonal reading entry 0

The COO and tril mutants first survived because the tests used a self-inverse permutation and k = 0. Both tests were sharpened.

4. Notes

  • No sparse layout in the IR. The generated loops are gathers and segment sums over tables. That is fine for assembly and products; the factorization in T2-7 works on the values with its own tables.
  • Function outputs. A SparseMatrix is returned by passing values and sparsity explicitly. A tree leaf for the decorator (sc.L with a sparse type) would be a small follow-up if wanted.
