Tier 3 · summary and review round

The generic primal–dual IPM: PIQP 0.6.2 as generated code · branch claude/tier3-ipm, tag tier3-complete · 27 Sep 2026

Summary. scaly.solvers.ipm.Solver generates PIQP 0.6.2 for one sparsity structure, from Ruiz equilibration to the result. It has a dense backend (condensed Cholesky) and a sparse one (SparseLDL on the whole KKT matrix), with PIQP's retries and iterative refinement. Every Tier 3 gate is met.

  • Fidelity: each backend takes the decisions of PIQP's run of the same backend.
    • Status parity on all 62 gate problems.
    • Decision traces match on 48/48 (sparse) and 47/48 (dense) of the problems where PIQP's own two backends agree.
    • The NumPy reference is matched step by step at full precision.
  • Speed: the sparse backend runs at 1.26× PIQP's warmed-up solve time where PIQP takes at least 50 µs, and at 0.81× its setup plus solve. The dense backend runs at 2.24×; its Cholesky kernel is 80% of a step (C-117).
  • Review round: five agents; every confirmed finding is fixed and tested, and four exact speed-ups cut sparse solves by 11–25%.
  • Suite: 2 218 passed, 42 skipped on the Mac. The IPM tests also pass with FMA contraction off and fast, which bracket what GCC does.

Speed

The performance review found cost in the generated step that PIQP does not pay. Four exact fixes give the same numbers and the same iterations:

  • max/min reductions in four interleaved lanes instead of one serial compare chain;
  • sorted segment extrema (CSC column ids) reduced run by run in a register;
  • Ruiz maxima taken per matrix;
  • the refinement tolerance and the KKT data vector moved out of the step.

An A/B on 8 problems cut sparse solves by 11–25% (DUALC8 −25%, QSC205 −19%) and dense ones by 1–38%. The final run of perf_2026_09_26_tier3/t3_4_ipm.py warms both sides up and takes minima of 50 samples each. Selected rows (ratio colours: ≤ 1.5 green, ≤ 3 amber):

Deviations from PIQP

  • Noise pivots. The dense backend also fails a Cholesky pivot below ε times its diagonal entry while refinement is off. Such a pivot's sign is rounding noise: on the reference path LAPACK fails exactly where it comes out negative.
  • Invalid bounds. A bound declared finite that arrives unusable stops the solve with INVALID_BOUNDS.
  • Nothing else. PIQP's other quirks (signed box maxima, the cost-scaling aliasing, IEEE 0/0) are reproduced.
