Case study E2 · Real-time Neural MPC

Plan case_studies_plan_2026_09_27.html, E2 · branch claude/case-studies · 27 Sep 2026 · code in examples/case_studies/neural_mpc/

Summary. The control-frequency table of Real-time Neural MPC (RA-L 2023, Table II), run with the authors' scripts on current acados. Scaly then generates the network's code in two places: inside acados, as the exact model's sensitivities, and in place of PyTorch, as RTN-MPC's Taylor surrogate.

  • The reproduction holds, with one correction. Table II is a 1D double integrator with an untrained MLP residual, not the paper's quadrotor.
    • The authors zero the network's output layer. With CasADi 3.8 that lets the expanded model drop the whole network: acados' generated sensitivities contain no tanh, and the naive column runs at a flat 12 kHz.
    • With output weights of 1e-6 instead, the network is evaluated again and the paper's pattern returns. The naive column wins on width-16 networks and collapses from width 128 (5 × 128: 134 Hz against RTN-MPC's 2.8 kHz here, 31 against 784 Hz in the paper).
  • The acados drop-in works. acados' generic external path accepts Scaly's casadi=True output, which was the plan's "check early" item. Two adjustments were needed: acados' casadi_int width, and the sensitivity matrix passed as a flat column-major vector, because Scaly's CasADi layer refuses dense matrices.
    • The exact model's sensitivities are 1.7 to 5.7× faster than CasADi's per call.
    • acados' linearization is 1.9 to 5.5× faster (5 × 128: 1.33 against 7.35 ms), with the same closed loop to 5e-13.
  • Against RTN-MPC, the exact model in acados beats PyTorch's surrogate for width-16 networks (10.3 against 3.6 kHz at 2 × 16) and loses from width 32 up (694 against 2812 Hz at 5 × 128).
  • Scaly's surrogate. In place of PyTorch, Scaly's surrogate is 29 to 38× faster than PyTorch's on width-16 networks and 5.4× on 12 × 32. It is 0.6× on 5 × 128 and 0.05× on 12 × 512, where PyTorch multiplies each layer by all ten points at once and Scaly does it point by point (CS-9).
  • Two more Scaly findings, both now in todo.md:
    • A model called as a Function has its forward pass computed twice when its value and derivative are both needed. That doubles the drop-in kernel (CS-10).
    • The CasADi layer's refusal of dense matrices is what forced the flat Sx (CS-11).

Against the plan's success criteria: "the drop-in at or above RTN-MPC for every width ≤ 128 with the exact model" is met at width 16 only. "The surrogate in C at least equal to RTN-MPC at 12 × 512" is not met (36 against 945 Hz). The full-stack variant (Scaly SQP-RTI) was not done (section 6).

1. The benchmark and the reproduction

  • The problem. Table II: x = (s, ṡ), u = s̈ with |u| ≤ 10, plus fD(x), an MLP with 2 inputs, 2 outputs and tanh.
    • The paper's layer counts and widths match MultiLayerPerceptron(2, width, 2, layers): 2 × 16 has exactly the tabulated 354 parameters. Its "182K" and "500K" are typos for 2.9M and 5.0M.
    • acados SQP-RTI: N = 10 over 1 s, ERK (RK4, one step), Gauss-Newton, full condensing HPIPM.
    • 50 timed control steps. Frequency is 1 / mean step time.
  • Upstream. ml-casadi's two example scripts at 44ec47f (the naive one was added after the paper), ported to current acados (00947dd, September 2026) with the network size as a flag. Nothing else needed changing.
  • The zeroed output layer. Kept as published, CasADi 3.8 constant-folds the network away. acados' wr_expl_vde_forw.c then has no tanh, and its linearization takes 5 µs at 2 × 128 and at 5 × 128.
    • The paper's naive numbers fall with network size, so its CasADi still evaluated the network.
    • Output weights of 10⁻⁶ N(0,1)/√width keep the dynamics nominal to about 1e-6 and make every column evaluate every layer. --out-scale 0 restores the published protocol.
  • Reproduced shape. On both machines the naive column beats RTN-MPC for 2 × 16 and 5 × 16 and loses from 2 × 128 and 12 × 32 on. The absolute frequencies here are 1.6 to 4.4× the paper's i7, and 7× for the naive 12 × 32. The exception is the naive 12 × 512, which is slower here (1.9 against 11 Hz); I did not track down why.

4. What the numbers say about Scaly

  • Exact sensitivities: Scaly is ahead at every size. This is the L1 lever working. The network stays dense loops, differentiated through those loops, and the kernel is 1.7 to 5.7× CasADi's expanded model. That is enough to beat RTN-MPC only where the network is small: RTN-MPC evaluates the network 10 times per RTI, the exact model 40 times with three tangent directions.
  • Batched dense layers: Scaly is far behind at scale (CS-9). The generated surrogate runs, for each of the ten points:
    • a matrix-vector product per layer for the value;
    • a two-column product per layer for the Jacobian.
    The 23 MB of float64 weights at 12 × 512 are read 20 times per call and stored twice, once per layout, which is 131 MB of C source against CasADi's 72 MB. PyTorch multiplies each layer by all points and directions in one product. Float32 against float64 accounts for 2.2× of the 22×; the rest is the missing batching. A vmap whose body multiplies by a constant matrix should become one matrix product over the mapped axis.
  • Call nodes recompute the forward pass (CS-10). Written as a model Function called in the sensitivity function, the Jacobians recompute the network beside the call's value: 60 against 31 µs at 5 × 128. The study writes the network inline; the documented way to write a model (a Function, as sc.integrators expects) pays the 2×.
  • The CasADi layer and acados (CS-11). acados is a real consumer of casadi=True, and it needs dense matrix arguments. The workaround (flat column-major vectors, which acados copies identically) is in scaly_impl.py. A transpose in the layer would remove it.
  • Deployment footprint. The RTN-MPC column needs PyTorch at run time; Scaly's surrogate is one C file with no dependency. .text and flash sizes were not measured here.

5. Tests and checks

  • New test. tests/integration/test_case_study_neural_mpc.py builds an acados-shaped expl_vde_forw for a tiny network. It renders the function with casadi=True, compiles it with casadi_int as int, and checks the CasADi query functions, including a zero-length input. It then calls the entry point from C with a column-major Sx and compares the value and both sensitivities against NumPy.
  • Mutation checks: 3 of 3 killed.
    • Reading Sx row-major.
    • Compiling without the casadi_int definition.
    • Dropping the input sensitivity ∂f/∂u.
  • Study gates, results recorded here:
    • The Scaly surrogate against ml-casadi's parameters, to 7e-14 in float64.
    • The drop-in closed loop against the naive one, to 5e-13.
    • expl_vde_forw CasADi against Scaly, to 1e-16.
  • Suite. 2 580 passed, 45 skipped. No source file under src/ changed.

6. Fairness notes and what was not done

  • Machine. Not the reference machine. Every grid cell ran with the one-minute load between 2.4 and 3.9.
  • PyTorch runs in float32. That is the paper's configuration, and ml-casadi casts the points itself. The float64 column is there so the implementation gap can be told apart from the precision gap.
  • Warm-up. Both columns get 20 warm-up steps before the timed 50; the authors warm up only RTN-MPC's network.
  • Not done: Variant C, Scaly's SQP in RTI mode. The plan routes it through sc.mpc, which has not landed; it would also compete with acados' HPIPM on a 10-stage QP where the QP takes 5 µs.
  • Not done: tracking error. Exact model against surrogate is not informative with an untrained network whose output is 1e-6. The paper's quadrotor experiments (Table III) need trained checkpoints, which the authors do not ship.
