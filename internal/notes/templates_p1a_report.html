Function templates P1a: Function becomes ConcreteFunction

2026-09-27 · branch claude/function-templates · plan: function_templates_plan_2026_09_27.md (v2), step P1a

Summary. A mechanical rename with no behavior change. Every code reference to the class in src/ and plugins/*/src now says ConcreteFunction, and Function stays as an alias until P2 gives the name to the template. Suite green, C snapshots unchanged, no new ty diagnostics.

What changed

  • 309 identifiers in 40 files, renamed by a tokenize pass over NAME tokens only: docstrings, comments and error messages keep saying "Function", the user-facing word. CasADi's ca.Function is skipped.
  • Three string spellings by hand: the quoted return annotation of with_device, the cast in ir/text.py, and ir/text.py's class-name test for rendering a callee as @name, which is code, not prose.
  • The alias lives in function/model.py (imported from there by tests/test_import_boundaries.py) and is re-exported by scaly.function, which also exports ConcreteFunction. scaly's public surface is unchanged.
