Function templates P2: holes, instances, is_concrete

2026-09-27 · branch claude/function-templates · plan v2, step P2

Summary. sc.Function is now the template, and sc.ConcreteFunction is a subclass of it. A declaration may leave shapes open (sc.L(), (2, None), sc.L(..., dtype="int64")). Each call binds the holes, traces the body once per distinct binding, and caches the instance under a deterministic name that is also its C symbol (double__3, rows__5, ident__3int64). A fully declared function is still traced at the decorator, is its own single instance and keeps its exact C symbol. The C snapshots are unchanged, and concrete calls cost what they did.

What changed

  • Object model. Function[**PS, **PN, SO, NO] (template) and ConcreteFunction(Function), both in function/model.py. A separate module would form an import cycle. The decorator returns a ConcreteFunction when no input leaf has a hole, and a Function otherwise. Output holes (output="y") are resolved by the trace as before and do not make a template.
  • Protocol.
    • is_concrete;
    • concrete: itself, or NotConcrete (a TypeError) naming the holes and the fix;
    • instances: {name: ConcreteFunction};
    • instantiate(*specs): one declaration per parameter, as in the decorator. That is a shape, a TensorType, a tree, or an example array or Expr; a tuple of ints is a shape, any other tuple a group's parts.
    Graph attributes (input_names, inputs, factory, ...) are declared on the base class for typing. On a template they forward to the one instance, so a holed template raises NotConcrete wherever a compiler entry inspects it, including entries nobody listed.
  • Holes. tree.Hole(dims, dtype, diff) replaces the bare Ellipsis as a leaf declaration. None dimensions are partial holes. An open dtype binds from an Expr argument (numerical arguments are coerced, to float64 by default). Tree.bind checks structure, then fixed dimensions and dtypes, in the call site's ValueError wording.
  • Keys and names. The key is the bound declaration's resolved types, so a symbolic and a numerical call that bind alike share one instance. Instance names are {name}__{tokens}, one token per hole: the bound dimensions joined by x (only the open ones of a partial shape), s for a scalar, and the dtype when an open dtype bound to something other than float64. Two bindings producing one name raise; creation-order suffixes are never used.
  • Call path. A second cache keyed on the arguments' flat shapes and Expr dtypes skips rebuilding the bound declaration on a repeat call; the instance's own call still checks structure and shapes. A template call costs 3.02 µs against a concrete one's 2.47.
  • Consumers.
    • while_loop instantiates a holed cond/body from init, the step index and params. vmap and scan refuse a holed callee with the instantiate hint, because a slice's size is not its stride.
    • lower_function, the five scaly.codegen renderers, render_program_c_source, render_expr_assembly and the viz entry points accept any Function and take its one instance.
    • The CLI treats any Function attribute as a function, not a factory: a zero-argument ConcreteFunction used to be called. It refuses a template with the export hint.
    • Lowering's name-clash refusal keys on the C spelling: f:_3 and f__3 used to reach the C compiler as a redefinition. The refusal now names both.
    • _flat_symbolic_call checks dtypes, not only shapes.
  • Public names. sc.ConcreteFunction and sc.NotConcrete, pinned in test_import_boundaries.py. The P1a alias is gone. docs/api/core.md and the package map are updated.

Tests and mutation checks

tests/function/test_template.py (16 tests) covers:

  • per-shape instances and one trace each, with a float, an int, a NumPy scalar and a 0-d array sharing one instance;
  • symbolic instantiation inside another trace, where f(a) is f(a);
  • two instances lowering to two procedures, and partial shapes;
  • a fully declared function being its own instance, and instantiate in all its forms;
  • the NotConcrete messages, the loop builders and while_loop binding its own callees;
  • open dtypes, and the collision guard (with a monkeypatched namer);
  • with_device, recompile, and the CLI (instance, zero-argument function, template);
  • a JIT cache hit from a fresh process, every inspecting entry refusing a template, and the fast path.

Also: test_two_names_with_one_c_spelling_are_refused in lowering, and typing checks for templates (instantiate, concrete, instances typed as ConcreteFunction; a ConcreteFunction assignable to Function and not the reverse).
