Tier 2 · review round and summary

T2-R · agent review, fixes, optimizations (C-113) and the Tier 2 summary · branch claude/tier2-sparse · 26 Sep 2026

Tier 2 is complete. Scaly now has sparse and dense linear algebra as generated code, and every gate in the plan is met, with one exception: the dense kernels at gcc -O2, which waits on your decision in C-107.

  • Sparse matrices are values: a fixed pattern with Expr values.
  • SparseLDL factors quasi-definite KKT systems.
    • Speed: within 1.0–1.5× of a QDLDL-class C factorization, and faster than it when unrolled on small systems.
    • Solves carry implicit derivatives, to second order.
    • Also available: refinement, inertia and health checks.
  • Dense Cholesky, L D Lᵀ and triangular solves are within 1.6× of OpenBLAS at -O3.
  • Examples: an SQP Newton step and a Kalman update show the pieces in use outside PIQP.

Review round. Five agents reviewed the whole Tier 2 diff:

  • lowering and in-place proofs;
  • AD rules;
  • linalg;
  • performance;
  • docs and tests.

They found 10 correctness defects, all fixed with regression tests:

  • 6 give wrong numbers silently;
  • 4 fail to build;
  • 2 of the 10 predate Tier 2.

The round also produced:

  • four optimizations: JIT calls 4.2 → 3.2 µs, an in-place adaptive refinement loop, and two generation passes no longer quadratic;
  • about twenty documentation corrections.

Suite: 1 460 passed, 88 skipped (1 421 before the round); the same four VM-only failures. ruff, ty and the strict docs build are clean. Mutation checks: 21 of 21 killed. Two needed a sharper mutant or an added test (details in §4).

Checked and found sound by the agents:

  • In-place proofs (both fuzzers ran on in-place and two-slot loops, with no difference between them):
    • ~1 000 random put/put_add/index_add chains;
    • ~1 400 random ragged chains.
  • Scratch sizing, dense lowering (n = 1–13, all flags, both paths) and int64 scalarization.
  • All Tier 2 derivative rules, first and second order, against finite differences.
  • No non-conservative sparsity pattern.
  • SparseMatrix against SciPy on 16 shapes.
  • analyze on 60 random graphs × 3 storages × 4 orderings.

Adopted from the agents' scratch tests:

  • sparse Hessians in K and mixed K/b, in both storages and both schedules;
  • matrix-RHS derivatives;
  • third order;
  • dense Hessians in the matrix against FD.

  • Why the generation gain is small. The remaining generation cost is spread across the whole pipeline: match.rewrite, node construction and walks at about 1.2 ms per scalar operation. That is C-111.
  • The in-place extension was fuzzed on 450 random constant-index loops (246 ran in place) against NumPy and the two-slot loop, with no difference.
  • One existing test changed. It expected a select body to keep two slots; the loop-level proof now correctly finds that it reads entry 0 and writes entry 3.

Recorded for later, from the performance agent:

  • C-114: unpadded update groups. A hand-written prototype is 1.6–1.7× faster on grid and MPC systems and beats the C baseline. It needs a two-level ragged op with its own rules.
  • C-115: a JIT cache key taken before lowering. Warm runs currently repeat all Python generation.
  • C-116: straight-line stores straight into the result, which halves gcc time.
  • C-117: double2 dense dot kernels and small-solve micro-fixes.

4. Tests and mutation checks

  • New regression tests cover every fix (§2) and every optimization. That is 39 more test cases; the node-ID baseline is updated.
  • Mutation checks on the fixes (14 mutants, all killed): fresh names, bit equality, -0.0 literal, vmap fallback, put winners, stale pattern, constant exponent, solve tag, rule tag, unread tangents, symbolic check, diagonal numbering, and hoisting (2).
    • The rule-tag mutant is killed only when both the jvp and the vjp names collide; gradients use the vjp.
    • The first symbolic-check mutant was a syntax error; it was redone with pass, and that version is killed.
  • Mutation checks on the optimizations (7 mutants, all killed): address fallback, steps length, steps call, the fuse boundary, the pack boundary, dependency tracking, and scalar refusal.
    • The pack-boundary mutant (a slot reused one statement late) changed only memory use and first survived; the property test against a linear-scan reference now kills it.

Scripts: perf_2026_09_26_tier2/review_optimizations.py, with re-runs of pr7_sparse_ldl.py and pr9_schedule.py.

Ready for the IPM, all generated code:

Open items that matter there:
